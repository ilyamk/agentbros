# Grow the Blender arsenal

Use this when a named shot needs a capability the current arsenal lacks. Start with `pnpm blender:arsenal status`; it separates approval, installation, local files and measured recipe proofs. A proposed extension is not approved; null cost is unmeasured. Pass `--proof out/qa/PROOF/index.json` for measured costs/settings. Recipe proof is technical evidence, not creative acceptance.

1. **Check built-in first.** Geometry Nodes, simulation zones, bundled Essentials and `scripts/blender/kit/` often suffice. Read the [built-in alternatives and shortlist](../../../../docs/blender-arsenal/README.md#researched-shortlist). Run `pnpm blender:recipe list`, `pnpm blender:assets --action search --query "NEED" --local`, then `pnpm blender:arsenal candidates` before repeating research. Record the missing capability as a memory gap (the orchestrator writes; leaf agents propose the entry).
2. **Research the specific gap.** Query the extensions.blender.org API with the actual Blender version/platform; inspect GitHub maintenance/release history and the asset's own licence page. Record dated evidence for GPL-compatible extension code; CC0/CC-BY assets (OFL fonts retain OFL.txt); automation and AI ToS; maintenance; declared and observed file/network permissions; accounts, wheels and native platforms; headless API; seedability and bake requirements; Blender min/max (max is exclusive); authoring versus render-time dependency; film value against built-in. Unknown terms stay unresolved. External GPL extensions are pinned, never copied into this dual-licensed repository. Record an observation with sources and uncertainty.
3. **Trial only with execution/download consent.** Inspect source and local ZIP before executing it: `pnpm blender:ext inspect --file PATH.zip`. After actual consent, `pnpm blender:ext trial --file PATH.zip --name CANDIDATE-RUN` uses a separate profile in `local/trials/`. New library adapters require injectable fetch and fake-network tests; there is no generic library-trial command. Use an isolated profile and already consented files for a native append/render trial. Profile isolation protects preferences, not the OS; extension Python still has the user's permissions. Never touch the user's Blender profile. Record trial commands, Blender/platform, seed, bytes, install/enable/setup times, render overhead, objects/polygons and frame-alone/range pixel differences, with sample counts. Keep failed evidence; no made-up zero costs. Record an observation.
4. **Evaluate and propose.** Use [the template](../../../../docs/blender-arsenal/_template.md); fill Verdict and Trial results, licence/ToS evidence, proof numbers and limitations. For an extension, `pnpm blender:ext propose --file PATH.zip --purpose "SHOT VALUE"` pins the archive and creates its evaluation. Present the benefit, permissions, cost and alternative with the one-line approval command: `pnpm blender:ext approve --id ID --consent "$OWNER_APPROVAL"`. Network/account candidates also need `--allow-network-account`. OWNER_APPROVAL must contain the user's actual decision; do not supply it yourself. A library-source proposal shows the exact manifest patch (status, consent, evaluation) for owner approval; there is no source-approve CLI. Acquisition remains separately consent-gated. Record an observation of the proposal; only the owner's words become a decision.
5. **After approval, pin and integrate.** Pin version, platform, SHA256, bytes and licence evidence; remote fetch still requires actual download consent. Approved extension install: `pnpm blender:ext install --id ID`; render via `blender:run --extensions ID`, never saved user preferences. Wrap the useful API in a typed helper or built-in recipe with strict parameters, seeds and tests. Add asset ids to an appropriate collection; record extension dependencies in the helper/evaluation, since collections contain asset ids only. Pass `pnpm blender:arsenal audit`. Record the integration observation and unresolved limits.
6. **Contribute and measure.** Follow [contribution gates](../../../../docs/blender-arsenal/CONTRIBUTING.md); contribute pins, evaluations, collections, recipes, helpers and rejected records, never binaries or personal local paths. Re-run `pnpm blender:arsenal --action eval --harness codex --out out/qa/arsenal-eval/RUN`. Compare identical task/schema/scorer hashes and models. Record the measured delta as an observation, not a claim of film quality. The orchestrator captures each step through `pnpm memory --add --type observation` (or `--type gap` for the missing capability) with evidence; leaf agents return proposed entries.

## Promote a successful shot into a recipe

Keep only the reusable capability: generalise bounded parameters (seed, timing, dimensions, density), reject unknown keys, put shot intent first in the docstring and literal META. Compose with an existing scene; do not erase the camera/stage or mutate other recipes. Use kit curves, camera roles, light moods and safe-frame reports. Simulations must bake with a fixed seed into `blender-arsenal/local/bakes/<recipe>/<hash>/`; hash parameters, source, Blender version and relevant dependencies. Test cache reuse/invalidation and failure atomicity. Compare decoded pixels of a middle frame rendered alone and in a range, including motion blur. Require a proof (seconds/frame, objects/polygons/instances, cache time, pixel delta, exposure/coverage/activity/flicker/contact sensors), inspect its sheet, and include a critique table: intent, visible success, flaw, repair, remaining limit. Preserve old/new evidence. See the [recipe contract](../../../../scripts/blender/recipes/AGENTS.md); run its pure and gated Blender tests before contribution. A one-off success does not prove the whole parameter range.

## Scoped FX discovery

Use `pnpm blender:arsenal candidates --capability fluids` (or `volumes`, `materials`, `science`, `pattern`) to include approved tools and recipe verdicts. `generators.json` pins built-in Mantaflow/volume grids and the original procedural surface library; add-ons remain in `extensions.json`. Recipe `requires` selects approved dependencies, with exact build/source checks at execution. Tissue and Molecular Nodes have scoped 5.3.0 integrations; five FX wrappers and the material library remain experimental. Read `docs/blender-arsenal/fx-realism.md` before choosing them for a final. A static molecule needs an explicit attributed local structure or public `pdb_id`; it is excluded from live replay.
