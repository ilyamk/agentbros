# Guarded Blender self-improvement

Run after every shot with any critic axis below 4, or whenever a needed capability was missing. The orchestrator owns the loop; critic and advisor are leaf agents. Existing authorisation covers software work; approval gates on production, plugins and spend remain in force.

1. Freeze a professional reference description BEFORE variants: what must read, material response, light shape, contact, motion beats and settle. Render the current recipe, open 3–5 actual key frames and record the run's gaps. Use 480×270, 8 samples and denoise for iteration, one Blender process at a time, isolated arsenal profile. Keep media ignored.
2. Dispatch a fresh `blender-critic` with the reference, frames and slop list. Never continue an old critic. Scores cite frames. A score below 3 on any axis means experimental; stills cannot establish continuous motion.
3. Collect `pnpm blender:arsenal status`, `pnpm blender:arsenal candidates --capability TAG`, `pnpm blender:improve gaps` and `pnpm blender:improve history --target TARGET`. Give critiques, gaps and these snapshots to `blender-advisor` in a fresh read-only session. It proposes at most three ranked typed changes.
4. Diagnose system versus shot. Reproduce the weakness with unchanged defaults and another seed/subject where appropriate. A one-off taste or briefing mismatch stays in the shot. A reusable defect belongs in the owning recipe default, material, kit function, sensor or rule. Generalise only the part that transfers. New behaviour with a different intent is a new recipe, with literal META, documented knobs and tests. Missing tools go through `blender:ext propose`, consented trials and `blender:arsenal candidates`; do not install on the user's profile.
5. Save the original diff, change ONE cause, re-render with identical seed/stage/settings/frame coverage. `pnpm blender:improve packet --baseline OLD --candidate NEW --reference "..." --out NEW_PACKET_DIR` sanitises media and builds reversed packets; `key.json` stays outside each opaque packet folder. Give only one folder per fresh critic. Use two independent sessions, one per order: `pnpm blender:improve judge --input PACKET/packet.json --out NEW_CRITIC.json`. `advise --input CONTEXT.json --out NEW_ADVICE.json` runs the advisor. Both invoke `codex exec --sandbox read-only --model gpt-6.1-sol`, no inherited conversation. MP4 requires actual frame inspection; sparse PNGs get `sampled-frames`.
6. Run sensors, determinism and regression tests. Each referenced evidence file must exist, be repository-relative JSON and contain its actual `pass` boolean; scoring verifies and hashes these reports. Write checks JSON: `{"sensors":{"pass":true,"evidence":["relative sensor report"]},"tests":{"pass":true,"evidence":["relative check report"]}}`. Score with `pnpm blender:improve score --key PACKETS/key.json --results C1.json,C2.json --checks CHECKS.json --out SCORE.json`. Missing orders, a tie, conflicting votes, failing checks or changed packet bytes cannot prove a win. Scores give means, per-axis deltas and experimental status. **A change lands only if it wins blind in BOTH orders and passes sensors/tests.** Otherwise revert your change, then log it. A win below 3 remains experimental; no production-quality claim follows from a relative win.
7. `pnpm blender:improve log --input ENTRY.json` appends a new tracked `blender-arsenal/improvements/<date>-<slug>.json`; strict `ImprovementLogSchema` records weakness, system/shot diagnosis, typed change, numeric A/B result, kept/reverted decision and stable gap ids/status. It never overwrites. Record unresolved misses, not just wins. `gaps` ranks open gaps from logs plus active Blender memory; a later explicit resolved status closes a tracked gap. `history --target` includes failures, so do not retry them unchanged.
8. Write local observations/gaps through `pnpm memory --add --type observation|gap --summary "Blender ..." --agent orchestrator --evidence PATH`. Include the stable gap id to deduplicate against tracked logs. Never turn an agent score into the user's confirmed lesson. `memory --consolidate` points to tracked logs; `creative-postmortem` uses them when diagnosing repeats.

Contribute only code, tests, the sanitised numeric log and a reference/critique evaluation, following [CONTRIBUTING](../../../../docs/blender-arsenal/CONTRIBUTING.md). No media, personal memory, secrets or absolute machine paths. Include exact commands/settings, timings, per-axis 1–5 critique, sensors, both-order result and what remains unverified. Do not retrospectively edit the reference or delete failed history to manufacture a win.
