# Model and asset production

Read the approved brief, project artefacts and root rules. Reuse approved media and version-pinned references first; import original harness outputs with `pnpm asset:import`. Preserve provenance, rights, card versions and audio ownership. Existing approval and no-spend instructions take precedence.

## Production loop

On `match.matched: false`, rephrase the task or pass `--category`/`--inputs`/`--outputs`; never pick from an unmatched list. Treat a lexical match as a weak signal: read its warnings and record the suggested memory gap.

1. **Find.** Run `pnpm models:pick --task TASK --project ID`; use `--use-case ID` or `--slot ID` for an explicit production task. Use `pnpm fal:find --provider any --task TASK --explain` for catalogue fallback; a strict verified-only filter excludes discovered Higgsfield models even when they have a documented schema, so inspect their exact evidence without promoting their tier. Compare candidates' reasons, price bounds, trust and retirement warnings. Inspect exact fields with `pnpm fal:models --schema ENDPOINT`. To filter by what a model accepts (end frame, audio, references, voice, input length), use `pnpm models:capabilities --capability end-frame,generate-audio --duration 5` (`--list` shows the vocabulary). A tier proves evidence coverage, not creative quality or live acceptance.
2. **Scaffold.** Run `pnpm fal:scaffold --endpoint ENDPOINT --out REQUEST.json`; fill its required fields and placeholders, using its exact input schema. New work uses `{ endpoint, input }`, with measured reference metadata in `context` where needed. Preserve approved legacy requests unless a deliberate upgrade is authorised. **Pack before request:** when the endpoint takes reference inputs and `pnpm refs:profiles --action for --endpoint ENDPOINT` reports a profile, never fill its reference fields by hand: plan, derive and pack them ([reference-preparation](../reference-preparation/SKILL.md)), get the user's pack approval, and validate the request `refs:pack --action request` emits; an unprofiled endpoint cannot be packed, so say so.
3. **Validate.** From the repository root, run `pnpm generate:model --request REQUEST.json --project ID --output public/projects/ID/assets/... --dry-run`. `--output` resolves from the current directory, not from `--project`, and the operation ID derives from it: resume with the same path from the same directory. Inspect endpoint/schema/input hashes, guards, media bounds, output kinds, warnings, quote and `executable`. Missing schema needs the returned maintenance action; planning never fetches automatically. Do not infer provider fields or quantities from a sibling endpoint or unsent defaults.
4. **Quote and budget.** Use `pnpm fal:quote --request REQUEST.json --project ID` and `pnpm budget --project ID` to inspect the exact operation and durable headroom. Unknown prices require an explicitly authorised positive `--max-cost-usd`; never invent one. For N variations, prepare a batch spec and run `pnpm fal:batch --spec BATCH.json --project ID --dry-run`; review aggregate high bound and policy verdict. Dry-run materialises immutable local requests without paid submission.
5. **Run after approval.** Before a paid submit, show the user the prompt verbatim, what must change and what must stay fixed (for video: which parts move), the acceptance criterion you will measure (`context.expect`, e.g. `{ "motion": "animated" }`) and the price with its source and any page/API drift. Their approval covers all of that, not only the amount; never trade the requested effect for safety (freezing motion to protect text) without asking. Submit the same validated request only after that approval, within durable budget bounds. A batch additionally needs `pnpm fal:batch --spec BATCH.json --project ID --execute --max-total-usd TOTAL`. Each variation has its own identity. Resume queued/running/unknown work with its original operation ID and frozen quote; reconcile ambiguous outcomes before any new revision. Never silently change endpoint or repeat a paid POST under another ID.
6. **Hand off by kind.** For video, read `metadata.motion` and `metadata.acceptance` and report the measured numbers before calling it done; a failed expectation is a failed take, not a success with caveats. Inspect published image/video/audio assets, GLB `model3d` assets, analysis text/JSON manifests or training weights/config manifests. Use `pnpm model:result --project ID --operation-id OPERATION` for an analysis summary and check its observations against frames. A pending job is unfinished. Record quote versus actual receipt separately and reconcile retained liability.

Produce `validated-generation-plan` in `pipeline/craft/model-and-asset-production.json`, or the owning stage artefact when its schema covers the fields: exact endpoint/schema/payload, reference pins, operation ID, quote evidence, budget headroom, expected result and reconciliation. Keep observed facts, creative decisions and unresolved assumptions distinct.

## Routing and review

Use the [category command map](references/fal-catalog.md) and [agent catalogue guide](../../../docs/fal-catalogue.md). Exact modern asset plans use `source: "fal-model"` and `metadata.operationRequest`; see [production routing](../../../docs/production-model-routing.md). Unknown prices and a higher trust tier never imply zero cost or a provider billing cap.

Keep stream/realtime jobs on their dedicated transports: [stream recovery](../../../docs/http-stream.md), [bounded sessions](../../../docs/realtime-sessions.md) and [realtime editor](../../../docs/realtime-editor.md). Interrupted streams cannot reconnect as a retry; socket writes are not provider acknowledgements. Approved stills are imported before making a fresh unsent draft. Whole-session bounds, finite limits and retained liability survive changes of transport.

Review the exact payload, provenance, rights, measured media limits, native audio/language policy and result contract. Fixtures establish offline coverage only; music and quality remain the user's judgement. A different cheap model or shortened quote cannot fund another physical operation.

## Higgsfield and cross-provider choice

Use `pnpm models:pick --use-case replace-person`, `--use-case influencer-photo` or `--use-case ad-variant` for Genjutsu character swaps, Soul / AI Influencer personas and Marketing Studio ad stills across providers. Compare labelled exact/tiered prices, floors, release dates and reasons; `pnpm models:compare` reports only evidenced equivalent savings. Scaffold with `pnpm fal:scaffold --provider higgsfield --endpoint ENDPOINT --out REQUEST.json`, retain `provider: "higgsfield"`, then `pnpm hf:quote --request REQUEST.json` and the usual `generate:model --dry-run` loop. Never reuse a fal payload for an identical Higgsfield ID. A schema-less candidate such as Genjutsu Light needs explicit `/estimate` validation (`hf:quote --provider-estimate`) or a schema; catalogue floors never admit a budget. Real people/third-party clips need `entity:card` consent and source-use permissions before provider processing.

Read [Higgsfield model choice and refresh](../../../docs/higgsfield.md) and [prompting guidance](../../../docs/higgsfield-prompting.md).


## Prepared Genjutsu: three operations

Use `object-swap` to replace only a selected person, face, outfit or object and preserve the rest; `motion-transfer` to rebuild the scene around source motion/camera; `restyle` to apply a current preset. Inspect the endpoint's `model:prepare --action profile` and follow [prepared inputs](../../../docs/higgsfield-prompting.md#prepared-genjutsu-workflow). Do not choose motion-transfer merely because the request says character replacement.

Before fresh execution, the orchestrator prepares an imported source segment/crop and ordered approved entity references with `model:prepare`. Complete its visual review from the actual board and full clip; record source-use permission through `film:rights --preparation ID`, including audio and placements, and the user's exact input approval. Preserve `context.modelPreparation` in the request and any asset-plan operationRequest. New requests without current preparation are blocked before upload/estimate or spending; historical durable jobs retain their original resume identity. A source-use or input approval does not replace the material/spend gate.

These modes are the general pack flow with their own entry point. Describe the target, requested change, invariants and other people in plain words; `model:prepare` compiles the attachment markers ([prompt markers](../../../docs/higgsfield-prompting.md#marker-prompting)), so never type them, and check on the board that each names the right attachment. Markers are not masks or a guarantee of identity fidelity.

When the source is missing, research dated market/category candidates via `motion:library`, then acquire authorised originals through existing import/media:fetch routes. No supported Higgsfield Motion Library feed/download API is established; an internal preview URL is not a cleared original. Leave unavailable sources pending. After generation, use `model:prepare --action result-board`, inspect the full source/result and record `--action review-result`; exact-byte identity, motion, scene, other-subject, temporal and audio review is required for delivery. Ask the user on reshoot.


For supplied content links, inspect `hf:media --action capabilities`, then resolve/acquire an exposed public original with `hf:media`. Static page metadata is supported; dynamic Motion Library pages without an exposed original stay pending or use a permitted direct URL/export. Bind checked image/video/audio URLs to exact schema JSON pointers in a new request with `--action bind`; retain `context.remoteMedia` in operationRequest. Public URLs pass through without upload, including arrays and nested character-reference images; do not invent fields for schema-less models. A prepared remix uses the receipt's imported assetId and `remoteSource` binding in a new preparation, only for an entire already conforming clip without crop/audio changes. Otherwise omit remoteSource and prepare a local derivative. Acquisition/revalidation downloads for inspection; this avoids reuploading, not all local reads. Fresh provider operations recheck bytes; queued resumes keep the original identity. See [remote media](../../../docs/higgsfield.md#public-content-links-and-checked-remote-originals). Select the task slot with `pnpm models:pick` before choosing the generation endpoint.
