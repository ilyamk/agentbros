# Playbooks — Agent Rules

Last updated: 2026-11-18

A playbook is one kind of content task, named the way a user asks for it ("cut my recording and add subtitles", "a product tutorial"). It is the orchestrator's first decision: the method, quality bar and tools for that task, pointing into the registries below it, never restating them.

| Layer | Answers | Lives in |
|---|---|---|
| Playbook | what is being made, how good looks, which method | `playbooks/<id>/` (this folder) |
| Route | how the work runs: film, footage, workflow, campaign or a project.json timeline (render, QA, delivery), and its next-step command; the template stage pipeline was removed (2026-11-17) | `src/lib/pipeline/route.ts` |
| Technique | for a film route, the film type: which chain steps run and with which tools | [film types](../docs/film-types.md) |
| Craft and roles | skills (`.agents/skills/`) and agents (`.agents/agents/`) | [agents index](../.agents/agents/README.md) |

## Choose, bind, proceed

1. Choose: `pnpm playbook --match "<the user's request>"` ranks candidates: score, matched triggers and request words, `notFor` neighbours, the matched `variant`. Read the top candidates (`pnpm playbook --id <id>` adds the film type's page, merged QA, read lists, intake, profiles, starter, variants, tagged lessons and `optionalSkills`: not shipped, install from upstream if missing, never block).
2. Read the answer's other fields first:
   - `existingProject`: the request names an existing project (an id after "проект"/"project", or a hyphenated id): continue it with `pnpm next --project <id>`.
   - `modifiers`: `reference-style` ("в стиле", "референс", "style of", "like this video", a YouTube, TikTok, Instagram, Vimeo or X link) or `replica` (only explicit copy words: "точную копию", "скопируй", "copy exactly", "replicate"). See Modifiers below.
   - `strength`: `clear` when the top score is at least 2 and leads the next by at least 1, or a lone candidate scores at least 1.5 (one specific phrase, no rival); `weak` otherwise, including a `tie` (with a ready `question`); `none` when nothing matched. Scoring: [guide](../docs/playbooks.md#matching).
3. Ask the user unless the strength is `clear`, and whenever the top candidate's `notFor` describes the request. Never take a weak match as a verdict.
4. Bind: `pnpm playbook --use <id> --project <id>` writes `pipeline/playbook.json` (`--by user` when the user named it); `film:init` and `footage:next` take `--playbook <id>`. Rebinding the same playbook keeps the first choice and never turns a user's choice into the agent's. Another playbook is refused (`FILE_EXISTS`): ask the user, then `--force`. A film or footage project refuses a playbook with no route or alternative of that kind; a project.json project accepts any.
5. Proceed: `pnpm next --project <id>`. A bound project's step answer reads the playbook's `AGENTS.md`, its `read` files and that step's `stepRead` files first, and carries the user's `memory` and, at a gate or delivery, `capture` ([in next-step answers](../docs/playbooks.md#in-next-step-answers)); an unreadable binding answers `playbookWarning`; an unbound one `playbookHint` and, from its film type, footage goals or recipe, `playbookSuggest` (the owners below).

When starting a film or recording with `film:init` or `project:new`, pass `--title` with a short name that describes the video in the user's language. Use the project ID for subsequent commands and file paths.

Playbooks are harness: every command reads them from the checkout that holds the code, whatever the working directory.

## Modifiers

Two modifiers apply on top of any playbook and are not playbooks themselves:

- **reference-style**: a film in the style of a given reference, for the user's own content. Skill [reference-to-video](../.agents/skills/reference-to-video/SKILL.md), combined with the playbook for the task.
- **replica**: an exact shot-for-shot copy, only when the user explicitly asks to copy a film. Skill [reference-replica](../.agents/skills/reference-replica/SKILL.md), film type `replica`.

## Coverage

Owners come from [coverage.ts](../src/lib/playbooks/coverage.ts), whose `GENERAL` lists the shared commands with reasons. A production command or library category needs a playbook naming it or a `GENERAL` reason, or `tests/playbooks-coverage.test.ts` fails. `pnpm playbook --uses <name>` shows which playbooks name a command, block, category, skill, agent, caption profile, style or template, and where.

## No playbook fits

Work continues on the route the material chooses (a film type, or footage:next for the user's recording); tell the user no playbook covers it. Known gap: dubbing of the user's recording (the `localise` draft names what is missing). After delivery, propose a draft playbook from the project; the orchestrator writes it on the user's go-ahead.

## Fields, maturity, adding one

[docs/playbooks.md](../docs/playbooks.md): the fields (intake, profiles, starter, variants, reviewedAt, evidence), maturity `draft` -> `ready` -> `proven` (only the orchestrator sets `proven`, after the user accepts a project recorded in `evidence`), review age, coverage, adding a playbook, lessons.

- `draft`, for users: the playbook works and its commands are checked, but its method is incomplete or untested on real projects; its `Done when` names what is missing. Say so before binding one, and expect more user decisions along the way.
- Triggers are trilingual (English, Russian, Chinese; 2026-11-17): users ask in any of them, so a new playbook gets all three and `--check` requires `zh`. A broad trigger that also fits neighbours goes in `triggers.generic` too. Measure every trigger change with `pnpm playbook --eval` against the labelled corpus ([matching](../docs/playbooks.md#measuring-it)).

## Checks

`pnpm playbook --check`; `pnpm exec tsx --test tests/playbooks.test.ts tests/playbooks-coverage.test.ts`.

- For supplied public media links, `pnpm media:fetch` downloads into the project with provenance; downloading does not establish publication rights.

Model selection (2026-11-15): production needs map to use cases and slots in [the slot guide](../docs/model-slots-guide.md); run `pnpm models:pick --task TASK` instead of naming a preferred model version.

Video remix (2026-11-15): `video-remix` is the draft three-mode Genjutsu playbook. Supplied source clips and character-reference images alone do not imply the reference-style modifier; explicit style/copy requests retain their modifiers.

Campaign route (2026-11-16): ad-experiments, catalogue-videos, reference-family, localise-campaign and content-series coordinate existing child playbooks through campaign:next; [method](../docs/campaign-production.md).

Step-scoped reads (2026-11-16): `read` holds only what every step needs; `stepRead` names files read at particular steps ([fields](../docs/playbooks.md#fields)). `playbook --id` names each field once; `--full` adds triggers and per-step tools.

Reference packs (2026-11-17): playbooks that generate shots (`ai-film`, `teaser-trailer`, `product-promo`, `avatar-presenter`, `video-remix`, and `ugc-ad` for inserts without a person) name `refs:profiles`, `refs:plan`, `refs:derive` and `refs:pack` and the `reference-preparation` skill; markers are compiled by `refs:pack` or `model:prepare`, never written in playbook prose.
