# Reference families

Last updated: 2026-11-16

## Start

Transfer a reference’s presentation method to new products. Use [campaign production](../../docs/campaign-production.md) to author the request.

```bash
pnpm campaign:production --project <id> --action plan --request <file>
pnpm campaign:production --project <id> --action init --request <file>
pnpm next --project <id>
```

## What good looks like

The family retains an intelligible compositional principle while showing authentic new material. A blueprint explains which timing and narrative functions transfer and which owner-specific elements must change.

## Method

1. Analyse the reference into a pinned ReferenceBlueprint before planning the family. Separate measured timing from creative interpretation.
2. Map each product to the blueprint slots and record required new evidence. Keep source-use permissions and brand identity separate.
3. Choose the appropriate existing child route for each treatment. Use film agents when adapting camera, performance or bespoke composition.
4. Compare the results against the blueprint’s keep and mustChange rules. Reject borrowed claims, branded interfaces or unsupported substitutions.
5. Ask for a package decision on the concrete five-product family, then let normal delivery validation judge the selected outputs.

## Tools

Use reference-analysis and reference-to-video for decomposition and transfer; choose engine-selection before authoring missing visuals. Exact copying belongs to the separate replica route only when requested.

Compare a representative product treatment against mapped blueprint slots before releasing the family. Preserve transferable functions and validate new facts separately; named presentation fixes return to a fresh critic.

## Anti-patterns

Do not replace analysis with a style adjective, copy another owner’s product interface or reuse reference timestamps as new speech alignment.
