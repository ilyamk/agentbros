# Motion library

A catalogue of reusable motion-design blocks for Remotion films, built so that an AI agent can pick, configure and combine them cheaply: by a one-line description and a picture, not by reading component source.

## What is in it

Blocks live in `src/motion/library/<category>/`:

| Category | Holds |
|----------|-------|
| `typography` | Kinetic and editorial type: lines, stacks, fitted headlines |
| `finish` | Shot-level polish: grain, bloom, vignette, aberration, light leaks, camera drift |
| `backgrounds` | Living grounds instead of flat fills |
| `ui` | Product interfaces that assemble and perform |
| `transitions` | Cuts that carry meaning between scenes |
| `camera` | Moves through a flat layout: push, whip, zoom-through |
| `three` | Real 3D: product stages, lit objects |
| `data` | Charts and figures that draw on |
| `scenes` | Whole shots composed from the blocks above |

Finish has three presets for `FilmFinish` (`preset="clean" | "filmic" | "tactile"`, in `src/motion/library/finish/presets.ts`): clean is grain 0.02 and a vignette of 0.08; filmic grain 0.05, vignette 0.18, a slow seeded drift and faint bloom; tactile grain 0.07, the paper texture of `texture-overlay` and vignette 0.12. Explicit props override a preset, and with neither the finish is grain 0.04 alone, as it always was.

Transition blocks take `seamFrame`, the frame from the block's start where the perceived cut lands; their `cut` cue sits there so `sfx:cues` can place the sound in a film.

The micro-craft helpers in `src/motion/timing.ts` (`intentCurves`, `hierarchy`, `followThrough`, `timeRemap`) sit under `match-cut`, `speed-ramp`, `hierarchy-reveal` and `camera-breath`; `texture-overlay` and `chroma-edge` (sparing) are finish layers.

`styles/` holds complete looks (palette, type pairing, motion personality and finish) that keep a film consistent across blocks.

Every block is a React component with a zod props schema and defaults that make a good-looking preview with no input. Each one renders on its own as a Remotion composition `Lib-<id>-<V|S|L>` (vertical 1080×1920, square 1080×1080, landscape 1920×1080) in every format it has been checked in.

## How an agent uses it

```bash
pnpm -s library:list --query "dashboard"   # compact catalogue, one JSON line, under a second
pnpm -s library:list --id film-finish       # props JSON schema, defaults, exports, preview compositions
pnpm -s library:list --styles               # available looks
```

`library:list` reads `docs/library/catalogue.json`, generated by `pnpm library:catalogue` from the live registry; it adds a `warning` when that file is missing or older than the library source, and `--live` reads the registry directly (about 20 s). The agent then opens `docs/library/previews/<id>.jpg` (early, mid and late frame) or `_<category>.jpg` (one tile per item), imports the block from its `importPath`, passes props, and checks the result with `motion:still` and `motion:strip`. The full workflow is the [motion-library skill](../.agents/skills/motion-library/SKILL.md).

## Previews

```bash
pnpm -s library:preview --id film-finish     # one item
pnpm -s library:preview --category data      # a category plus its overview sheet
pnpm -s library:preview                      # everything (slow: one bundle per category)
```

Sheets are about 1200 px wide JPEGs of 20–40 KB, committed with the code so that agents can look without rendering. Each category may have its own `preview.tsx` entry, which keeps bundles small.

## Guarantees

- `tests/motion-library.test.ts`: unique kebab-case ids, schemas that parse their defaults, non-empty formats, positive durations, existing import paths inside the category directory, unique style ids, and `catalogue.json` ids matching the registry (slow: loads the live registry).
- `pnpm lint`: no CSS animation, GSAP, framer-motion, `requestAnimationFrame` or timers anywhere under `src/motion/`. Every frame is a pure function of the frame number, so renders are repeatable.
