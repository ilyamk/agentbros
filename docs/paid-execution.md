# Durable fal execution

`generate-image`, `generate-video`, `generate-model`, `generate-ai-image --provider fal`, `generate-lipsync`, `rmbg`, `upscale` and the five legacy video demos perform **one resumable step**. Use the same arguments/`--operation-id` to resume. A successful JSON envelope with `metadata.state=queued|running` and empty outputs means the operation remains pending; it is not a completed asset. Only `state=published` exposes validated files.

`--dry-run` validates input and quotes offline, without keys, reservations, writes or provider calls. With `--project`, `generate:model --dry-run` also returns `metadata.maxAdmissibleUsd`: the most a new production job could reserve now (per-job limits, ceilings, existing commitments and the repair reserve), read from the operation store or, before one exists, from the first policy the brief would install (2026-11-17). A refused admission fails with error `BUDGET_EXCEEDED` (not `INTERNAL`); its message names the numbers, for example "Production allocation is $0.17 (ceiling $0.20 minus 15% repair reserve); requested $0.20.", and `details` carries them. Modern operation requests use exact schemas through `--request path.json`; arbitrary endpoints are rejected. Stream/realtime/training/voice result execution requires dedicated workflows and is not enabled in this media CLI.

Each fal operation also pins publication intent: resolved output path, media/artifact kind, model and sorted reference asset IDs. An explicit operation ID refuses changed publication intent before provider polling or downloading, including for already published jobs. Identical resumes retain the original quote and request ID. Older journal entries without that pin remain readable for accounting, but cannot be silently rebound through the new fal publisher; inspect/reconcile their original request and import already delivered files rather than submit a replacement. Existing project configurations and legacy model aliases remain unchanged.

New paid jobs also record a V2 canonical input digest with UTF-16 code-unit key ordering, independent of locale and insertion order. Legacy provenance hashes remain unchanged. Default-ID lookup checks both formats before estimates, uploads or admission; a resumed job keeps its original ID, quote and hash. Frozen original input bytes can prove a legacy match across locales. Without such proof, an unresolved historical attempt at the same destination blocks automatic replacement; use its original environment/ID and reconcile it first. No historical job is rewritten in bulk.

Higgsfield reservations retain exact estimated bytes in `quotedRequestBody`, then validate uploaded/prepared inputs semantically before freezing the wire body. Retries verify the saved raw-byte digest and send the same body with the same idempotency key. New pricing proofs pin their original collation locale; historical proofs without that field retain legacy validation and may require their original locale.

Paid execution requires `--project`. The initial local policy uses the brief's finite budget capped at $10, with 15% for repairs; a null or absent `budgetUsd` authorises nothing, so paid work is refused until a ceiling exists. `budget --project ID --ceiling-usd N --answer "<the user's words>"` configures an explicit policy: raising the ceiling, or a first one above zero, needs the user's own words (recorded with who, when and the answer in `operations.json` `policyEvents`); lowering needs none, and the MCP `budget` tool cannot raise it. Unknown prices require `--max-cost-usd N`: this records a user planning bound, **not a provider-enforced cap**. Publication does not release the liability or invent an actual price. Supply a verified billing receipt to `budget --receipt file.json --operation-id ID`; no-charge releases likewise require an explicit confirmation file. Durable jobs write no `cost-ledger.jsonl` rows, so `cost:report` also lists jobs with a paid attempt and no receipt or release as `metadata.pendingReconciliation` (`operationId`, `endpoint`, `reservedUsd`) and `reservedUnreconciledUsd`, outside `totalUsd`, and its Markdown names the exact `pnpm budget --project ID --operation-id OP --receipt <receipt.json>` command for each (2026-11-17).

The SDK currently overrides global retry configuration with queue-submit retries. The production REST adapter deliberately performs one POST, with redirect replay disabled. The request ID is committed before polling. Lost submit responses become `unknown`; never create a replacement operation before reconciliation. Failed downloads retain provider results and retry publication without another submit. All returned images are downloaded, inspected, imported with immutable hashes and unknown billing provenance, then published atomically per file.

Queue URLs: the submit's `status_url` and `response_url` (https, `queue.fal.run`, ending in `/requests/<request id>[/status]`) are stored on the job as `providerUrls` and used for every status and result poll, because the app route often differs from the endpoint ID. Invalid URLs are dropped at submit, keeping the request ID. Without them, the caller's `queuePath` (the OpenAPI submit path from `openApiRoutes(model).submitPath`, leading slash removed) is the route; it is stored on the job as `queueRoute`, so resumes keep it. Jobs with neither (historical ones) poll the old endpoint-root route.

Result kinds: `providers/fal-results.ts` `extractArtifacts(outputSchema, result)` splits a result into files and top-level data fields, guided by the endpoint's output schema when given (`resultSchema`). Only the files that are downloaded must be on the trusted fal host list (else `VALIDATION`); other untrusted URLs, such as an echoed input URL, are recorded as `untrustedUrls` and never fetched. `mediaKind` takes any `OutputKind`:

- `image`, `video`, `audio`: as before (the older result fields first), inspected with ffprobe.
- `model3d`, `weights`, `file`: the files of that kind, preferring the output's extension, are downloaded under the same size limit and published at the output path. GLB and glTF are checked (header, version, length, JSON chunk) and imported as `model3d` assets; GLB inspection reads only the header and JSON chunk. `.safetensors` weights are checked by header and offsets and published as files, not registered assets.
- `text`, `json`: nothing is downloaded; an immutable manifest at `pipeline/model-results/<operationId>.json` holds the endpoint, operation, request ID, input hash, data fields, trusted file list and `untrustedUrls`.

No live API acceptance has been performed. Tests inject fake queue/fetch responses and use local synthetic media. All fal generation calls in production scripts and `src/lib/apis/fal.ts` now use this boundary. ElevenLabs follows its separately documented synchronous boundary; free resource search/download calls are not paid fal jobs.

Library callers supply `generation: { projectId, output, operationId?, maxCostUsd?, ... }` (or a second context argument for background removal/upscale). Missing context rejects before any provider request. Pending work throws `PendingFalOperationError` with the same resumable metadata. Published library URLs refer to validated **local files** (`file:` URLs); use file APIs to read them. The save helpers already publish the files and do not download them again.

Background removal, upscale and lipsync encode local references as deterministic data URIs, validated by local ffprobe, limited to 32 MiB per file. Their actual bytes participate in operation identity: changed input creates a new derived identity, while an explicit operation ID refuses changed input. The standalone `uploadFile` helper requires explicit project context; storage upload does not submit a generation job. LatentSync requires a video source. Legacy demos preserve unrelated existing files and run one resumable step per scene; `--operation-id` is a batch prefix with scene suffixes. `--force` permits verified output replacement, never deletes the asset directory.

Pollinations remains an explicitly labelled prototype fallback. Its dry run is entirely offline; its usage and licensing should be reviewed before production publication.

ElevenLabs TTS/music/SFX/alignment/Scribe also reserve budget and journal the POST. Repeated caller retries replay a checksummed response from `.cache/paid-responses/{projectId}`; response bodies never enter `public/`. Audio is decoded with ffprobe before replacing an existing take. Project-local output/input paths infer the project; external paths require `paid.projectId` or CLI `--project`. Unknown rates need `--max-cost-usd`. A missing provider request ID is recorded as a **local correlation only**, with billing uncertainty preserved. A live local work lease serializes submit/publication; an interrupted process never implies a free retry.

Package aliases load an existing `.env` inside the shared CLI error boundary (the pinned project Node runtime); help and dry-run work without `.env` and do not load it. Exported environment variables continue to take precedence.

ElevenAPI list rates were refreshed from [the official API pricing page](https://elevenlabs.io/pricing/api) on 2026-10-11: v2/v3 USD 0.08/1k characters, Scribe v2 USD 0.22/hour, music USD 0.15/minute. Quotes preserve the source/date and never become invoices. The page does not establish a universal forced-alignment rate, so alignment now needs an account-specific bound rather than silently being treated as free. Provider POSTs reject redirects and have explicit timeouts.

## Batch quotes, forecasts and execution

`pnpm fal:batch --spec BATCH.json --project ID` defaults to an offline dry-run. A `FalBatchSpec` names one endpoint, `baseInput`, `context`, unique `variations` (`id`, optional `inputPatch`), `outputDir` and `assetIdPrefix`. Objects merge recursively; arrays and scalar values replace. Every variation is a separate physical operation, with ID `<batchId>.<variationId>` and asset ID `<assetIdPrefix>-<variationId>`. Output extensions follow the catalogue's first output kind (PNG, MP4, WAV, GLB, or JSON; weights use safetensors, generic files bin).

```json
{
  "version": 1,
  "batchId": "shot-takes",
  "endpoint": "fal-ai/kling-video/v3/turbo/pro/text-to-video",
  "baseInput": { "prompt": "A quiet shoreline", "duration": "5" },
  "variations": [{ "id": "a" }, { "id": "b", "inputPatch": { "prompt": "A shoreline at dusk" } }],
  "outputDir": "public/projects/film/assets/takes",
  "assetIdPrefix": "shore"
}
```

The batch freezes its spec, output identities and endpoint requests, plus raw-request/provider-input hash receipts after validation, at `pipeline/batches/<batchId>/`. Reusing the ID with changed content refuses; `--revision v2` appends `.v2` to the batch ID and creates new identities. Dry-run materialises those local files but never reserves or contacts a provider. It calls `generate:model --dry-run` for each operation and returns aggregate `quote: {low, expected, high, bounded}`, `unknownCount`, per-operation errors and warnings. Per-operation `quoteInput` retains the exact request, validated plan and input hash when the executor does not expose pricing quantities separately. Bounded quotes expose their `evidenceKind` on each operation.

The forecast uses the same operation store as `budget`: remaining ceiling, production headroom after the repair reserve, per-job limit, existing commitments and paid attempts per asset. Verdicts are `fits`, `exceeds-ceiling`, `op-exceeds-max-job`, `unknown-price-needs-bound`; `invalid` covers failed validation or attempt/ambiguous-submit conflicts. Unknown prices require `maxCostUsdPerOp`; the aggregate includes that bound, with no claim of capped provider billing. Existing jobs retain their frozen quote and add no new reservation liability. Historical identity receipts avoid current schema/price lookups on resumes; older simple inputs must match the stored provider-input hash directly. Published output hashes are checked before skipping a job, and status reads IDs independently of the catalogue.

`pnpm budget --project ID --forecast BATCH.json` and `pnpm fal:quote --project ID --spec BATCH.json` return the same forecast without writing files or configuring policy. `fal:quote --request REQUEST.json` accepts either request form for one quote. Read-only calls pass request JSON on the child process's stdin. An unconfigured budget previews the executor's initial policy and reports a warning.

Execution requires `pnpm fal:batch --project ID --spec BATCH.json --execute --max-total-usd N`, a `fits` verdict, and an explicit total at least the aggregate high bound. Operations run sequentially through the ordinary durable executor. Each operation is pinned to the lower of its dry-run high bound and `maxCostUsdPerOp` when set. Zero-cost quotes fail closed if the per-operation executor cannot admit a zero bound. The batch stops at the first failure or ambiguous submission and reports its operation ID. Queued/running jobs remain pending. Repeating the same command resumes those identities; published operations are skipped. `--status` reads each saved job, including missing jobs as null, without submitting or writing.

`fal:quote --provider-estimate` is an explicit network opt-in requiring `FAL_KEY`. Its POST to `/v1/models/pricing/estimate` uses `{estimate_type: "unit_price", endpoints: {endpoint: {unit_quantity: n}}}`. The response is labelled `providerEstimate`, with request and observation time, and never changes the reservation bound. API-priced quantities derive from the quote divided by its recorded unit price; other endpoints use one provider unit per physical operation as an explicit estimate assumption. MCP exposes local `fal_quote` without this network flag, and `fal_batch` in dry-run spend mode with nested output-path scoping.

## Platform pricing evidence in reservations

New bounded API-derived quotes attach `platform-pricing-api` evidence built from the trusted local price record, with exact endpoint = model, source, date, unit, rate, converted pricing and digest. When public-list evidence exists it takes precedence. The job schema accepts both kinds, and a new reservation rebuilds evidence from today's trusted record; a forged payload fails even with a recomputed digest. An API-derived bounded quote without that evidence cannot pass fresh execution pricing or reserve against an API pricing source. API generated-second prices also bind quote duration and units to the provider input's explicit positive duration. Historical resumes validate the stored evidence and identity without refreshing prices or enriching old jobs.

## Pause, stop and cancel (RFC 0004 D12, 2026-11-17)

`pnpm console:control --state paused|stopped` makes every non-control command of the project fail with `PAUSED`. Pause is soft: jobs already submitted keep running and their results are kept. The job store refuses with `PAUSED` to reserve a new job or submit a reserved one while the project is paused or stopped, even inside a batch or workflow started before the pause, and an ambiguous job with a saved body and no provider request ID is not resubmitted. A campaign run skips the tasks of each paused child project with a `PAUSED` note. Every `--project` value is judged as written and lowercased. A command whose script runs exactly the job one `--operation-id` names (`generate:model`, `generate:image`, `generate:video`, `generate:music`, `generate-lipsync`, `rmbg`, `upscale`) is still admitted when that job is already submitted (a provider request ID, state `queued`, `running`, `unknown`, `result-ready`, `downloading`, `validated`, or `failed` with a kept result), so it completes; repeated `--operation-id` or `--project` values and scripts that derive ids from it (`generate:voiceover`, `align:captions`) are refused. Only the user resumes. The user's own decisions from the console (`film:approve`, `film:policy`, …) still run while paused: the console server signs each command it spawns with a console grant, `AGENTBROS_CONSOLE_GRANT` = HMAC-SHA256 of the canonical JSON `{argv, issuedAt, project}` under the token of `out/console/session.json`, with `AGENTBROS_CONSOLE_GRANT_AT`; `runScript` admits it only for that exact argv and project and for 60 seconds, then strips it from the environment so children never inherit it (`src/lib/console/grant.ts`). What it authorises, exactly: running through the pause, and, for `recut:plan --approve` only, recording the user's edit-hash approval together with the intent the console server writes just before that spawn (`pipeline/inbox/intent/<decision>.json`: decision id and the sha256 of the exact argv, which carries `--decision=<id>`; fresh for 60 seconds, consumed by the approval, removed when the child exits; `src/lib/console/intent.ts`). The grant alone approves nothing; it never lifts the step lease, budget admission or any other approval gate. It is also the only source of console attribution: a command is the user's on the console (`actor: "user"`, `channel: "console"` in the journal and in approvals, feedback, ratings, memory, policy and ceiling grants, control changes) only when its grant verifies at `runScript`'s start (`src/lib/cli/channel.ts`); `AGENTBROS_ACTOR=user` and `AGENTBROS_CHANNEL=console` alone are claims, journaled as the agent's on the CLI with `data.claimed`, so they neither count as evidence that a console decision applied nor silence a failure notice, and a resume they claim is still flagged as resumed via the CLI. Trust boundary as D15: any process of the same OS user that can read `session.json` can forge one; as defence in depth the hooks' `guard` role denies agent tool calls that read or write `out/console/session.json`, name `AGENTBROS_CONSOLE_GRANT`, set `AGENTBROS_ACTOR` or `AGENTBROS_CHANNEL`, or pass `--print-token`, for every project ([harnesses](harnesses.md#hooks)). A stop also lists the in-flight jobs (`planned` to `unknown`) with their reservations. `pnpm job:cancel --project ID --operation-id OP --answer "<the user's words>"` cancels one job: an unsubmitted job locally (reservation released as `not-submitted`); a submitted Higgsfield job through its cancel URL, settled as `cancelled` with a confirmed no-charge release only when Higgsfield's status reads `canceled` (otherwise `requested` or `refused`, the reservation kept); fal (its adapter has no cancel call), stream, realtime and synchronous jobs, and jobs past the provider's work, are recorded on the job as `unavailable`. The latest request is stored as the job's `cancellation`.
