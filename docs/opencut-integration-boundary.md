# OpenCut native integration boundary

Source rechecked 2026-10-11, without installing/running upstream applications or executing their setup scripts. Public Git/source reads are separate from service API acceptance; no model/resource API requests or spending occurred.

The current rewrite snapshot remains [e668010778568641babef2cc40be4703ae6916d6](https://github.com/OpenCut-app/OpenCut/tree/e668010778568641babef2cc40be4703ae6916d6). Its [README](https://github.com/OpenCut-app/OpenCut/blob/e668010778568641babef2cc40be4703ae6916d6/README.md) describes editor API, plugins, MCP and headless mode as future capabilities. The inspected apps/crates provide scaffolding rather than a versioned project import, edit, render or readback protocol. The platform therefore continues to return an explicit unavailable native OpenCut capability.

Classic snapshot [cf5e79e919144200294fb9fed22a222592a0aeea](https://github.com/OpenCut-app/opencut-classic/tree/cf5e79e919144200294fb9fed22a222592a0aeea) supplies concrete internal project types and storage. [Project types](https://github.com/OpenCut-app/opencut-classic/blob/cf5e79e919144200294fb9fed22a222592a0aeea/apps/web/src/project/types.ts) include scenes, active scene, rational media time/FPS, canvas and schema version. [Storage service](https://github.com/OpenCut-app/opencut-classic/blob/cf5e79e919144200294fb9fed22a222592a0aeea/apps/web/src/services/storage/service.ts) persists projects in IndexedDB and media in OPFS. These internal stores do not establish a supported external project-file import/export API. Writing directly into an existing creator browser database would risk migrations and originals and is not an implemented adapter.

Adapted ideas already work in our own platform: exact source/output timing, explicit ripple edits, transactional batches, undo/redo and revision-checked review UI. Current interoperable results are baked media, caption sidecars and the tested OTIO/FCPXML subsets. Those exports are useful finishing artifacts; they are not claimed to load natively into OpenCut. A creator can manually use a compatible media output as a new source; native project round-trip remains unverified.

The next native integration requires an upstream versioned editor/import contract. Acceptance should use a separate synthetic project, import immutable originals, apply revision-bound edits to a copy, read back source trims/tracks/timebase/captions, compare with TimelineIR and test interruption without repeating an ambiguous mutation. This is an external prerequisite, not a placeholder implementation or a fabricated MCP server. The core Remotion/FFmpeg workflow remains fully usable while the prerequisite is absent.
