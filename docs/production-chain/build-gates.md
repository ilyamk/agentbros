# Build gates

Sensor gates, block choice and hero-shot tournaments of the [production chain](../production-chain.md): read at beat-sheet, animatic, build and measure.

## Slop signatures

The three sensor gates also block the defaults a generated film falls into, each with its fix ([slop catalogue](../../design-reference/slop-catalogue.md)). plan:check fails a linear curve on a moving entrance (`curve-linear`) and copy held far past its reading time (`text-hold-long`), and warns on a shot of three or more layers that names no entry order (`entry-hierarchy`); these stay out of its risk score. motion:check counts `SIMULTANEOUS_ENTRY`, `TEXT_CENTRED_ALWAYS`, `EMOJI_TEXT` and `SLOP_PALETTE` (purple-blue gradients, frosted glass), and the build step runs it with `--safe-zone` set to the brief's format. film:measure warns on `motion-spread` (the whole frame moving at once) and `fast-motion-sharp` (fast motion without blur), with the ceiling raised to a reference's own reading. `pnpm lint --project <id>` warns, without failing, on emoji and purple-blue gradients in the project's code; its render rules (determinism, native media, `STATIC_PATH`, `CSS_BG_IMAGE`) fail, and the animatic and build steps run them as the `project-lint-clean` done check. These signatures block in the promo profile too. Which thresholds are calibrated on the reference corpus, and which legs only warn because calibration could not validate them, is in [calibration](../../design-reference/calibration.md). A sensor earns its gate on evidence: `judge:calibrate` scores it on labelled pairs from `ref:degrade` (a reference segment against copies made worse on purpose) and lists it under `eligibleGates` only at accuracy 0.85 or more on six pairs or more; its critic mode measures the same blind, both-order creative-critic that judges tournaments ([calibration](../reference-analysis.md#calibration)).

## Which blocks

Block choice is a craft rule (`design-reference/craft-rules.md`, handed to look, beat-sheet, animatic, build and fixer): `sparing` items never by default; type bimodal (hero 50–95% width when type is the shot, a ~10% caption over picture); light grounds and ground swaps as a cut device; real UI (`capture:app`, or the `ui-*` kit at reading scale with `ui-camera-read`) over drawn placeholders; kinetic blocks for type builds; `blender-plate` for a hero product; effects only when the idea calls for them.

## Shot tournaments

For each micro-task of a film the technique is chosen by explicit criteria, not taste. The motion director sets each shot's `function` (hook, reveal, proof, transition, emphasis, cta, breath: the corpus's index) and `weight` (`hero` for the shots that carry the film, else `support`), picks two or three candidate techniques per hero shot from `pnpm ref:corpus` (`techniques.byFunction.<function>`: how professional films do that job, with timing, ease and sound), and names the film's `signature`: one element no library block supplies, taken from this film's idea, and the shots it lives in.

At the build, the motion engineer builds each candidate of a hero shot as its own composition (or the film's composition with another props file) and runs:

```bash
pnpm shot:tournament --action prepare --project <id> --shot <hero> --variants CompA,CompB[,CompC] --techniques mask-reveal,scale-punch [--range auto|shot|whole] [--allow <rules>]
```

It renders each variant's shot frames (`auto`: the whole composition when it is shot-length), runs motion:check with the brief's safe zone (the final-frame checks only on the film's last shot; `--allow` takes intended exceptions exactly as motion:check's `--allow` does, each with its reason, and the variant's sensor row names the failing counters with their counts, `textOffStage 3`, and how many findings a rule took out) and film:measure's shot legs (`motion-spread`, `fast-motion-sharp`, `flash-risk`) on it, and measures duration, motion onset after the cut, energy, spread and sharp share. Each is placed against the corpus band (p25 to p75) of the shot's function: duration and cut offset from that function's techniques; energy, spread and sharp share only from corpus metrics of the same name and unit. A feature with no band is listed as unavailable, never guessed; the distance is the mean of the rest. The nearest reference technique of the same function (closest first span) gets a `motion:strip --vs` sheet next to each variant; with no reference video each variant gets its own strip. Labels A to C follow a seed hashed from the project, the shot and each variant's composition, props hash and render hash, so the same inputs give the same labels. The record is `pipeline/tournament/<shot>.json`; the packets for the critic, every pair of surviving variants in both orders, are `out/<id>/tournament/<shot>/packet-<pair>-<order>.json`, naming only labels, `variant-<label>.mp4` and `strip-<label>.jpg`.

A variant that fails a sensor is out. One survivor wins alone; none leaves the shot undecided until variants are fixed or replaced. Otherwise the orchestrator dispatches a fresh creative-critic with the packets (`film:next` says so while the build waits on `tournament-decided`); the motion engineer, who made the variants, never writes the results. The critic opens them blind, reads the [slop catalogue](../../design-reference/slop-catalogue.md), and answers `{schemaVersion: 1, shotId, seed, judgements: [{pairId, order, winner, reason}]}`; then:

```bash
pnpm shot:tournament --action judge --project <id> --shot <hero> --results <file>
pnpm shot:tournament --action status --project <id>
```

A pair counts only when both orders name the same winner. The winner has the most agreed wins; a tie goes to the smaller corpus distance, then to the label. The rationale states the numbers: net wins, each pair's outcome, sensor values and corpus distances. `judge` refuses results for another seed, a packet left unjudged or judged twice. The decision is also written to memory as an `observation` scoped to the playbook and the build step, without a project: "a <function> hero shot was won by <technique>" in the words of `--techniques` (without them nothing is recorded, with a warning). The same line from a later film counts as a sighting, which `memory --consolidate` can turn into a rule proposal; judging the same tournament again counts nothing.

The build's done rule adds `tournament-decided`: every hero shot has a decided tournament, and its winner is what `build.json` mounts: its `composition`, or `shots.<id>` `{composition, props}` when the shot is mounted inside the film, with the props file hashed again at the check. A plan without hero shots passes.

Two plan:check gates guard against sameness across films. `signature-element` fails a bespoke film whose plan names no signature, or one in shots it does not have. `cross-film-repetition` compares the film's hero blocks (from `cue-placements.json` with their props hashed, else the plan's blocks) with the last two other films recorded in `memory/usage/` (local memory): it warns when a hero block appeared there with the same props, and fails when every hero block was a hero of one of those films. A replica is not asked for a signature. Blocks with no placement hash as `{}` props, so two films naming the same unplaced hero block count as the same use. `film:done --step build` records the film's blocks; `pnpm library:usage --record --project <id>` does it by hand and `--list` shows them. Both gates stay out of plan:check's risk score.
