# Choosing models through task slots

Use `pnpm models:pick --task "animate photo" --project PROJECT` or an explicit slot such as `pnpm models:pick --slot video.image-to-video --class hero`. The [generated table](model-slots.md) lists slots, concepts, categories and candidates. Selection is offline and deterministic; it creates no generation job and reserves no budget. `avc_models_pick` and `avc_models_slots` expose local read-only discovery through MCP.

The requested class comes from `--class`, project preferences, the project's `pipeline/brief.json` quality tier, then `hero`. Quality tiers map `quality` to `hero`, `balanced` to `balanced`, and `fast` to `budget`. Selection tries the requested class, each lower class, then each higher class, retaining slot order within a class. For example, budget tries budget, draft, balanced, hero. Constraints and the planning budget apply to every class. Equivalent models with equivalent parameters use the cheaper provider; the response reports both prices. Slot membership adds a reason to `fal:find` without changing its ranking.

## Prices in pick

Each slot has an optional `reference` setting for planning: video uses 5 seconds, 720p and 16:9; images use one image at 1 MP; voiceover uses 1,000 input characters; transcription, denoising and stems use 60 seconds of input audio. Music uses 30 seconds, SFX/foley 5 seconds. Slots with no meaningful price quantity use `{}`. The generated table prices each candidate at its slot setting, including candidates which fail capability checks.

Explicit flags override the reference: `--duration`, `--aspect`, `--resolution`, `--chars`, `--audio-seconds`, `--images` and `--megapixels`, and `--audio on|off`. Constraints parsed from `--task` override references too. Only supplied flags/task constraints filter capabilities; reference-only settings are price assumptions and do not reject endpoints lacking that control. Results report the effective `referenceSetting` and `referenceFields` supplied by defaults; price labels say “at reference setting” when any defaults were used. References are planning assumptions, not a provider output-size guarantee. The strict schema also supports `inputMegapixels` and `inputVideoDurationSec` for reviewed table settings.

`--max-usd` accepts exact/tiered totals and sourced approximate estimates within the limit. Seedance video tokens use the tracked tariff and explicit planning dimensions; the filter uses the expected price plus its existing 5% local forecast margin. Per-character rates use `max(1, ceil(chars / 1000))`; input audio uses seconds or seconds / 60; images use the requested count. Megapixel prices use the tracked first/extra MP rates and decimal-MP upper rounding, multiplied by image count; input MP charges need an explicit `inputMegapixels` setting (zero otherwise). Each computed label cites its source and formula. Pricing audit documents the dimension table, all candidates and remaining gaps.

GPT Image and Nano Banana have no tracked public per-image token quantities, so image count and area cannot bound their token bill. Compute seconds, undefined units and absent operation-specific tariffs also remain unknown. Catalogue “from” floors remain unbounded. These candidates appear in `needsQuote` in fallback order if they pass every non-price check, with an endpoint-specific scaffold command and the exact `generate:model --dry-run` command to run after filling actual inputs. A dry run can still require a token forecast or an authorised bound; it cannot manufacture unavailable usage evidence. The response includes a message even when no model passes. An explicit failing pin still returns `pick:null` and its best alternative.

With `--allow-unknown-price`, the first eligible unknown/floor in selection order can become the pick, with a warning. Approximate estimates warn that `generate:model --dry-run` is authoritative. Always scaffold and quote the final request before generation; selection creates no forecast context, changes no admission/budget rules and guarantees no provider billing cap.

For image/video input endpoints with no aspect field, or an aspect enum containing `auto`, a requested aspect warns “aspect follows the input; crop/prepare the source to 9:16” instead of rejecting. Prepare the source accordingly. Video operations without a controllable duration similarly warn that length follows the source; explicit incompatible controls still reject.

`--model ENDPOINT --provider fal` pins an exact endpoint/provider. A failing pin returns `pick:null`, its rejection reasons and a best alternative; selecting that alternative requires a new choice. Retired slot candidates never pass. Retiring catalogue endpoints are rejected with a warning. Unverified entries require owner evidence or a recorded `unverifiedAccepted` reason and retain an “unverified contract” warning. When no curated candidate passes, the same constraints and task specialism govern catalogue fallback, labelled `fromCatalogue:true` and “not in the slot table”. An unresolved task returns `matched:false`.

Projects can keep `pipeline/model-preferences.json`:

```json
{
  "version": 1,
  "pins": [{ "slot": "image.generate", "provider": "fal", "endpoint": "example/model", "reason": "Owner's project preference", "at": "2026-11-15T00:00:00Z" }],
  "avoid": [{ "slot": "image.generate", "provider": "higgsfield", "endpoint": "example/model", "reason": "Unsuitable for this project" }],
  "defaultClass": "balanced"
}
```

Project pins precede class ordering; avoid rules still apply. Preferences cannot waive catalogue, capability, trust or price checks. `AGENTBROS_MODEL_SLOTS` selects another validated table for local experiments and isolated tests.

The owner maintains the tracked JSON through atomic, locked CLI edits:

- Add an active candidate: `pnpm models:slot --slot image.generate --add example/model --provider fal --class hero --why "Quality judgement" --evidence-owner "Owner's verdict"`. Add a hero first in an empty slot; other classes follow. The endpoint must exist, be active and have a schema. Orders and provider/endpoint pairs must be unique within the slot.
- Activate a proposed candidate: `pnpm models:slot --slot image.generate --promote example/model --provider fal --class hero`. Promotion requires verified tier, existing owner evidence, or `--accept-unverified REASON` (recorded on the candidate).
- Remove a model from selection while retaining history: `pnpm models:slot --slot image.generate --retire example/model --provider fal`. Keep another active hero before retiring the last one.
- Change order: `pnpm models:slot --slot image.generate --move --endpoint example/model --provider fal --order 3`. Choose an unused order; gaps are allowed.
- Set freshness: `pnpm models:slot --slot image.generate --review-by 2026-12-15`.

`pnpm models:slots --check` checks catalogue/schema/status, active evidence, heroes, coverage, price sanity and review dates. Empty slots warn “slot has no candidates”; populated slots without an active hero fail. Overdue reviews and budget candidates pricier than the hero at the reference setting warn. `pnpm models:slots --write-doc` rebuilds the generated page; `--check-doc` detects drift. `pnpm regen` includes that generator. Arena evidence stores rank, URL and date, never raw ratings; generated pages attribute [Artificial Analysis](https://artificialanalysis.ai/) whenever arena evidence exists.

Record a generation verdict with `pnpm models:verdict --project PROJECT --operation-id OP --accepted` (or `--rejected --reason TEXT`). It appends only `pipeline/model-verdicts.jsonl` and refuses unknown operations. `pnpm models:stats --project PROJECT` or `--all` reads existing operations and cost ledgers, joins current slot membership, and reports generations, failures, acceptance and average known cost. Running/planned jobs are excluded. The first recorded verdict per operation defines first-pass acceptance; unjudged operations do not enter its denominator. Actual receipts take precedence over the latest ledger actual/estimate; unknown costs are excluded from the average and reported as `unknownCostGenerations`. Endpoint membership may associate an operation with several slots; counts across slots are therefore not additive.

## Freshness

The daily `models:refresh` PR adds higher versions from the same provider, family and variant as proposed `candidate` entries, after their predecessors. It retires catalogue-gone entries with a dated note; retiring/deprecated entries, budget/draft prices above the active hero at the slot’s reference setting, overdue reviews and catalogue categories without a use-case/slot mapping are flagged in **Slot proposals** in the refresh report and JSON metadata. Prices use bounded planning evidence or the candidate's sourced approximate reference estimate. Missing prices remain unknown. The optional `model-use-cases.json` mapping is read when present. No external rating service is called, and no candidate becomes active automatically.

Review and merge the PR to accept its proposed candidates, then run `pnpm models:slot --slot SLOT --promote ENDPOINT --provider PROVIDER` to activate a chosen successor. Promotion still needs verified tier, owner evidence or `--accept-unverified REASON`. The generated table is rebuilt when proposals change the JSON. `pnpm models:refresh --dry-run` lists planned provider steps and proposals from local catalogue/price snapshots without network or writes.

`pnpm models:stats --propose` reads verdicts across local projects and prints aggregate first-pass acceptance per slot/provider/endpoint. The CI runner has no local projects; acceptance is an owner-driven local step. Record it with `pnpm models:slot --slot SLOT --endpoint ENDPOINT --provider PROVIDER --evidence-acceptance`. The evidence stores accepted and judged counts plus a date and source, without project names or operation IDs; its `generations` denominator counts only operations with a first recorded verdict. Repeating the command on the same day replaces that day's local aggregate evidence. Unjudged generations and subsequent verdict revisions do not change first-pass acceptance. Operations and cost ledgers remain read-only.

## Use cases

`src/lib/models/model-use-cases.json` holds 44 production tasks derived from the playbooks, with Russian and English phrasings, applicable playbooks, preferred slots and notes. Run `pnpm models:pick --use-case text-card`, `--use-case photo-motion` or `--use-case replace-person`; `--task "hero фото товара с надписью"` resolves the matching use case before the concept map. Exactly one of `--slot`, `--use-case` and `--task` is required. The response includes `useCase`, the selected slot and `alternativesSlots` in preference order.

Matching shares `normaliseTaskTokens` with the task map: case, ё/е, punctuation and deterministic suffix normalisation. Every token in a recorded phrasing must match; the longest matching phrasing wins, then the use-case id breaks a tie. No partial-word, embedding or external inference is involved. Explicit slot ids stay exact. Unmatched tasks continue to the concept map; an unknown explicit use-case id returns `matched:false`.

The file also records all 28 catalogue categories shared across fal and Higgsfield: 20 mapped to slots and eight excluded with a production reason. Category mappings explain media-level fit; they do not establish an endpoint's specialism. Every use-case slot must exist, and the coverage tests require at least one active candidate reachable from each task. The complete use-case and per-slot inventory is in S3 verification.

`AGENTBROS_MODEL_USE_CASES` overrides the loader path, just as `AGENTBROS_MODEL_SLOTS` overrides the slot table. The test memory helper defaults both to temporary copies of small fixtures. Dedicated tracked-table tests load both repository paths explicitly; unrelated tests remain independent of curation changes.

## How the table was built

Walk both providers' tracked category files first, accounting for every category as a mapping or explicit exclusion. Read each playbook's method and variants, then turn its asset needs into use cases and preferred slots. Within a slot, compare category/input/output fit, schema limits (resolution, duration, native audio, reference counts and aspect choices), version recency within a family, trust tier and reference-setting price. Discovery dates are not release dates. Provider capability facts do not prove creative acceptance.

Each candidate's `why` records that reasoning and its reference setting: one output image at 1 MP where a per-MP tariff supports an approximate comparison, otherwise five seconds at 720p/16:9 where those fields exist. Evidence uses dated provider/catalogue documentation, except the owner's 2026-11-15 image and video verdicts. Those verdicts put the current owner-selected family first in the four image slots and three video slots specified by the owner. Older verified versions remain available. Other hero choices are capability/trust judgements awaiting creative feedback, not measured quality rankings. Unknown or floor prices cannot establish a budget class; labels retain uncertainty.

Token-metered image models have no `referenceEstimate` without tracked public per-image guidance. Their independent token tariffs remain authoritative and require forecasts in the generation dry-run. Non-token per-MP image estimates state the assumed output size and excluded input processing explicitly; they are approximate planning figures. A different output size or reference set requires a fresh quote. No new generation, paid call or external rating request was made to construct this table.

Provider-exclusive character and source-motion workflows are included where their schemas fit. Offline contract fixtures pin the tested Higgsfield schemas and music routes; “verified” proves local request/guard/result coverage, never a live result. Equivalent provider prices are compared only when the schema parameters and audio settings are comparable. Schema-less proposals remain pending. An unverified endpoint becomes active only with owner evidence or a recorded `unverifiedAccepted` reason (four utility slots: image/video denoise, video cut-out, voice clone).

Agent-facing recommendations refer to use cases/slots and `pnpm models:pick`. Provider-specific prompting, legacy facts, verification history and fenced examples retain concrete names. Exact factual exceptions live in `src/lib/models/model-instructions-allowlist.json`.

## Price comparison matrix

`src/lib/models/price-scenarios.json` names the standard scenarios for every slot. Video compares 10 seconds at 480p, 720p and 1080p, 16:9, with separate audio-off/audio-on columns where the tariff distinguishes them. Images compare one image at 1 MP and 2 MP; voiceover uses 1,000 characters; input audio/transcription uses 60 seconds; music 30 seconds; SFX/foley 5 seconds; avatar/lipsync 10 seconds; 3D one model. Other operations retain a one-call placeholder with an unknown price when their usage is unbounded. These are planning settings, not guarantees that an endpoint can produce every size or duration. Unsupported schema settings show `?`; a missing resolution control warns that the variant fixes resolution.

The generated `src/lib/models/price-matrix.json` and [comparison tables](model-slots.md) carry candidate × scenario prices. `$` means exact tariff/request estimate, `≈` approximate (including token forecast margins and MP rounding), `~… typ` a typical historical average per call, `≥` an unbounded catalogue floor, and `?` unknown with a cause. Each cell records its source and observation date, and formulas where applicable. The source order is exact tariff/formula (including parsed Higgsfield tiers), approximate tariff or sourced reference estimate, applicable historical typical, floor, then unknown. Audio columns coincide when no distinct tariff is recorded. A variant with no resolution control may have the same price in several columns; its output size remains fixed by that variant.

Every candidate has a separate `perCallTypicalUsd` column, including videos and audio. fal's free historical estimator reports past usage per API call, without the duration, character count or quality of those calls. One image or one 3D model can use that average as a **typical**, without a size/quality guarantee. It cannot price ten seconds of video, 1,000 characters or 60 seconds of input audio. Typical cells are never multiplied for multiple images or other quantities. `--max-usd` can accept a matching one-call typical with the warning “typical historical average; dry-run quote is authoritative”. Floors never satisfy that filter.

`models:pick` reports `scenarioPrices` and the separate typical column for its pick and alternatives. Exact request pricing wins. If it is unavailable, a matching scenario can supply a price; scaling uses only the same candidate and unchanged shape, audio, area and reference inputs along an evidenced linear unit. Supported units are seconds, input audio seconds, image count and character blocks (ceiling to the tariff's 1,000-character blocks). The label says “≈ from scenario X scaled ×k”. Token video with additional reference seconds, fixed request charges, unknown units and floors do not scale. The runner and budget admission still require their existing request-specific evidence.

Refresh with `pnpm fal:pricing --historical --slots --resume` (requires `FAL_KEY`, free read-only estimates), then `pnpm models:slots --write-doc`. Historical requests contain exactly one endpoint and run at concurrency two, with bounded 429 backoff and dated `.cache/fal-historical/` checkpoints. The default scope includes active/proposed slot candidates and their catalogue successors; `--all` selects the active fal catalogue; `--endpoints a,b` selects explicit endpoints. Partial refreshes keep older records for failures and set `syncedAt` to null. `models:refresh` runs historical pricing after list pricing and rebuilds both generated files even if no slot proposals changed. Missing keys are visibly skipped. `--check-doc` checks both artefacts. Offline verification and class additions are recorded in the S5 audit.

A specialist slot with only one real endpoint can declare `alsoClasses` while retaining its primary class and unique endpoint. This shares availability across class requests; it is not evidence of an independently cheaper model. Candidate docs and `unverifiedAccepted` reasons remain visible.

## Contracts

- `src/types/model-slots.ts` owns the strict table, candidate/evidence, reference estimate, project preferences and verdict contracts; owner edits use `models:slot`. Optional strict `ModelReferenceSettingSchema` supplies duration, aspect, resolution, image/MP and input character/audio/video quantities; discovery price kinds include `approximate`. `alsoClasses` lets a single endpoint serve multiple planning classes.
- `ModelUseCasesFileSchema` validates ru/en production phrasings, preferred slots and catalogue category mappings/exclusions.
- `src/types/price-matrix.ts` owns standard scenarios, historical per-call records and matrix cells. Existing table files remain valid.
- Tests: `model-slots*`, `model-use-cases`, `model-slots-pricing*` and `price-matrix*` (formulae, scaling, fake historical sync, picks, coverage, budget guards); `tests/helpers/memory-root.ts` isolates `AGENTBROS_MODEL_SLOTS`, `AGENTBROS_MODEL_USE_CASES`, `AGENTBROS_FAL_PRICES` and `AGENTBROS_FAL_HISTORICAL_PRICES`.

## Unit semantics from fal model pages

`pnpm fal:pricing --docs [--slots|--all|--endpoints a,b] [--resume] [--changed]` reads the public `https://fal.ai/models/<endpoint>/llms.txt` Pricing section without a key or generation call. The default scope matches historical pricing: slot candidates and catalogue successors. Requests use concurrency two, three bounded attempts, clamped Retry-After delays and same-day checkpoints in `.cache/fal-docs-pricing/`. Partial failures retain previous evidence and leave `syncedAt:null`; successful pages without a Pricing section remove stale semantics. Resume caches absent sections, repairs an incomplete final checkpoint line and refetches records whose saved API unit or rate changed.

`pnpm fal:pricing --docs --reparse` re-parses **every stored quote offline**, with its original observation date, API snapshot and catalogue mode default. It preserves `syncedAt`, makes zero network requests and supports `--dry-run`; scope, date and checkpoint flags cannot be combined with it. This updates `src/lib/models/fal-unit-semantics.json` after parser changes. Regenerate both matrices afterwards with `pnpm models:slots --write-doc`.

The strict version-one schema in `src/types/fal-unit-semantics.ts` remains compatible with earlier records; `AGENTBROS_FAL_UNIT_SEMANTICS` overrides the file. Records retain the page URL, Pricing quote, observation date, API snapshot, optional example, rounding rule and conditional tariffs. The pure parser uses an epoch observation-date sentinel unless supplied a date. The offline regression corpus contains the 1,207 real ambiguous quotes observed on 2026-11-16 and their available API snapshots. Bare repetitions of the API unit stay ambiguous with reason `Page repeats the API unit`, separately from genuinely unclear prose; ambiguous pages leave the existing API unit table and discovery conversions available.

Supported quantities include generated seconds, measured input video seconds, output images and megapixels, video megapixels (`width × height × frames / 1e6`), frame blocks, requests, input character blocks, input audio minutes and generated audio seconds. Explicit resolution × audio grids can also distinguish voice control. Base-duration tariffs carry `baseSeconds`, `baseUsd` and `extraUsdPerSecond`; shorter durations remain unknown. `clips` lists exact duration/resolution prices and never interpolates to other durations. Missing resolution tiers return `no page tariff for <res>`. Per-sample audio requires a positive sample count; discovery uses the schema default or one sample. Unsupported minima, reference surcharges, processing-time tariffs and incomplete conditions stay ambiguous.

Each stated example total is checked, including resolution lists, duration ranges, dimensions before or after frame counts, approximate MP display, currency rounding and both audio totals. Frame-derived prices always stay approximate: frames equal output seconds times the schema's `fps`/`frames_per_second` default, or 24 with an explicit assumption. Scenario resolution/aspect supplies planning dimensions; request quotes still need measured dimensions. Decimal image megapixels remain approximate. Mode tariffs require an identifiable schema default; they do not silently select the first mode. Promotions are conservatively parsed to the stated **regular** tariff with a note. Manually recorded `validUntil` on a tier or record supports an expiring promotion with `regularUsdPerUnit`; dates include the whole UTC day, timestamps expire at the specified instant, and expiry without a regular rate returns unknown.

Reviewed registry/public tariffs retain priority, including Seedance token formulae; page per-second estimates cannot replace them. Page-derived scenario rates remain approximate unless the selected rate equals the API rate. Fixed clips and base-plus-extra formulae remain approximate. With page/API drift, a per-unit page rate (single or the applicable resolution/audio tier) and the API rate are compared and planning uses the higher one (2026-11-17; formerly a single page rate kept the API rate and tiers the page rate); promotional and schema-default page rates, fixed clips and base-plus-extra formulae keep their page tariff. An endpoint without a `resolution` input whose page names one resolution (for example FLUX-3 drafts at 720p) is priced at that tier. `generate:model --dry-run` reports `metadata.priceDrift: { pageUsdPerUnit, apiUsdPerUnit, used }`; the formula label also names it. Labels carry the formula, page quote, URL and observation date; `priceDrift` also records disagreements. These prices are **planning-only** and never become sealed paid evidence or authorise spending.

## Catalogue price comparison

`pnpm models:prices --scenario 10s-720p --category text-to-video --provider any --limit 30` ranks active catalogue endpoints using the tracked standard scenarios. `--slot video.text-to-video` restricts membership to that slot's non-retired candidates. `--kind exact,approximate` selects evidence kinds; `--max-usd 1` excludes floors and unknowns as well as prices above the bound. Results sort by USD ascending, with unknowns last and provider/endpoint tie-breaks. Every result includes its kind, label, formula when available, source and observation date. This is a price ranking, without a creative quality judgement or a claim that every endpoint supports the scenario. `models:compare` retains its separate equivalent-endpoint savings calculation. The read-only `avc_models_prices` MCP tool accepts the same filters.

`src/lib/models/price-matrix-catalog/<provider>-<category>.json` covers each active fal and Higgsfield catalogue entry once. A category receives the union of scenarios attached to slots with that category, in scenario-file order; categories without a slot use `1-call`. The shared `scenariosForCategory(category, slots, scenarios)` mapping supplies these definitions. Catalogue cells use the slot matrix's same tariff, historical, floor and unknown precedence, without importing a slot candidate's reference estimate. `generatedAt` is the newest catalogue or price evidence date in that shard, never the time the generator ran. Higgsfield discount freshness is evaluated at that source date for a reproducible snapshot; request-specific dry-run quotes still check current prices. Cells remain compact, with one endpoint row per line. `AGENTBROS_PRICE_MATRIX_CATALOG_DIR` overrides the shard directory for isolated work.

`pnpm models:slots --write-doc` rebuilds the slot page, slot matrix, catalogue shards and `out/qa/model-prices/price-gaps.md`. It reads the old gaps counts before writing and retains the previous baseline when the current counts have not changed. The report gives coverage by kind, normalised unknown reasons, category × scenario gaps and the 30 slot-candidate endpoints with most unknown cells. `--check-doc` checks every artefact and the complete shard set, including obsolete category files. Unknowns never mean free; approximate cells preserve their formula/evidence, typical historical calls do not price scaled scenarios, and floors remain unbounded.

The daily refresh runs fal list pricing, changed documentation pricing (`fal:pricing --docs --changed --resume`), all-catalogue historical pricing (`--historical --all --resume`) and Higgsfield scenario pricing (`hf:pricing --sync --resume --scenarios`). It finishes with `models:slots --write-doc` after slot proposals have been saved. Existing evidence survives failed price refreshes. Offline tests build from fixtures and tracked data; live free refreshes are a separate owner-run operation.
