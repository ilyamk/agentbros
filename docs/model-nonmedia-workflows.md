# Durable model artifacts and draft workflows

`generate:model --request operation.json --project ID --output naming-identity --max-cost-usd BOUND` supports Kling `create-voice` and all eight FLUX.2 training/edit endpoints with their exact bundled official OpenAPI input/output schemas. Training uses the durable fal queue REST transport (one submit, no SDK auto-retry). The output argument is a stable operation naming identity for nonmedia workflows; the returned output is an immutable manifest in `pipeline/model-artifacts/`. Voice manifests expose the provider `voiceId`; training manifests reference content-addressed `assets/models/*.safetensors` and config JSON. Files are size limited, trusted HTTPS downloads with redirects refused, JSON/safetensors headers and tensor byte offsets verified, then hashed. No pickle weights are loaded. Provenance includes endpoint, provider request ID, operation ID and input hash; provider-terms/input-rights must still be satisfied. Receipts never label reserved estimates as actual payments. Query strings are removed from manifest source URLs.

Failed downloads retain the raw provider result and reservation, and resume publication without another generation. Manifest and artifact hashes are checked on every published resume. An ambiguous submit retains commitment and needs provider reconciliation. Unknown prices need an explicit planning bound; this does not cap provider billing.

Seedance `draft: true` returns a video preview, seed, and optional provider draft ID according to the verified schema. The CLI requires a draft ID for successful draft publication and saves original endpoint/region/input hash/credential fingerprint before submission. Completion derives caller identity, draft creation time and ID from that intent and the transactional provider job result, including when preview download failed. Caller-authored draft context is not trusted. The fingerprint binds the exact original credential without storing it; key rotation requires account reconciliation, not automatic rebinding. Seven-day expiry uses the original local job creation time conservatively. Draft generation and completion are separate budgeted operations. Only the global completion endpoint is documented: US draft completion is rejected rather than silently rerouted; a verified provider US-completion/account contract is required to enable that path.

Modern media AssetSpecs use source `fal-model`, an exact `metadata.operationRequest`, and an approved `metadata.maxCostUsd` when price bounds are unknown. The dispatcher preserves immutable request files and stable operation IDs; queued/running/unknown are pending, not completed. Local reference URLs require a separate upload workflow and must not be invented.

## Streaming and realtime capability gap

The installed primary fal SDK implementation (`@fal-ai/client/src/streaming.js`, `realtime.d.ts`) was inspected locally without network API calls. Streaming issues a direct POST and learns `x-fal-request-id` only from the response; losing the stream does not provide a verified queue-status/result recovery route. Realtime is a WebSocket session with input buffering/throttling, multiple sends, temporary-token refresh and per-result request IDs. The available schema discovery does not establish billable message counts, dropped-frame charging, cancellation refunds, or a bounded reservation per message/session.

These transports remain explicitly non-executable. Enabling them requires a dedicated durable session/message ledger, verified pricing bounds, persisted acknowledgements, disconnect recovery, deterministic deduplication and provider billing reconciliation. Queue inference/training never substitutes for these transports. No live compatibility or provider billing tests were performed.

## Catalogue trainers

Endpoints categorised as `training` also use nonmedia admission, including `blackforestlabs/flux-3/klein/base/trainer`. Their catalogue training price remains unknown: a fresh execution requires a positive explicit `--max-cost-usd`; dry-run without it is non-executable. Reservations and resumes use the existing durable jobs and frozen quotes.

The endpoint's output schema drives `extractArtifacts`: weights must have a `.safetensors` extension and pass header/tensor validation; config JSON files pass JSON validation. These files use the same content-addressed model store and immutable provenance manifest. There may be multiple weights/config files, and a config is optional when the endpoint schema permits it. Other result files are not published by the trainer path. Tracked FLUX.2 trainers keep their original field mapping and publication behaviour. Dataset captions and archive contents still need inspection before submission; a schema contract does not inspect a remote ZIP. Verification is offline only.
