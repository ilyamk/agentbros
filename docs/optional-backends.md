# Optional backends and finishing handoffs

The default Remotion/FFmpeg pipeline is unchanged. Use `pnpm tsx scripts/backend.ts --action capabilities` for a truthful capability registry, `--action probe --backend blender|resolve|hyperframes-html` for local version checks, and `--action export --timeline IR.json --assets assets.json --original-timeline-id ID --output HANDOFF` for an immutable local finishing package. No external editor mutation occurs through this CLI.

## Export contract

`ExportAssets` maps every media `assetId` to an absolute original path, media kind, exact source `timebase` and `durationFrames`, optional dimensions and explicit embedded `hasAudio`. Original hashes are verified before/after handoff. Timeline intervals are half-open. Missing assets, conflicting source FPS/trim bounds, invalid inputs and unbaked procedural/layout/audio automation payloads are rejected.

OTIO JSON uses the official `Timeline.1`, `Stack.1`, `Track.1`, `Clip.2` media-reference map and `LinearTimeWarp.1` schemas. Independent audio/video tracks, gaps, source FPS, trims and positive linear playback rates are exported. An OTIO time effect does not change item duration: our source-range duration is the displayed duration expressed in source FPS, and the time effect maps it onto the original source span. Original trim end, rational rates, complete IR and exact caption timing remain in metadata. Standard OTIO fields use doubles; metadata fractions are authoritative for audit/readback. Third-party applications may interpret effects differently and need readback QA.

FCPXML 1.10 exports a connected-lane, cut-only subset with independent audio/video lanes, exact rational second strings and per-source frame durations. Retiming and crossfades are rejected rather than approximated. Embedded audio is included only when `hasAudio: true` is supplied. Sequence/source dimensions come from explicit metadata. Import into a particular editor has not been live-verified.

Captions follow source trims and playback rate through the shared compiler, delivered as `captions.exact.json` and SRT. SRT rounds starts down/ends up to milliseconds. Native editor caption tracks, karaoke styling and application-specific titles are not silently substituted: sidecars require explicit finishing import and review. Exact caption metadata is preserved in OTIO.

References: [OTIO serialized schema](https://opentimelineio.readthedocs.io/en/latest/tutorials/otio-serialized-schema.html), [OTIO time effects](https://opentimelineio.readthedocs.io/en/latest/api/python/opentimelineio.schema.html), [Apple FCPXML reference](https://developer.apple.com/documentation/professional-video-applications/fcpxml-reference). Exports are original implementations; no third-party source was copied.

## Resolve recovery protocol

`prepareHandoff()` writes export/SRT/exact-caption files, original SHA256 values, expected compiled timeline and a checksummed manifest. `executeResolveHandoff(directory, adapter)` accepts a configured local adapter with a supported Resolve 19.x/20.x probe and complete clone/import/readback/original-fingerprint capabilities. The adapter receives the original ID only for fingerprint and duplication; import/readback receive only an independently returned clone ID. Original-ID clones are rejected. A local worker lease serializes dispatch. Clone/import intent is persisted before mutation; acknowledgement loss never triggers blind retry. Repeating a completed handoff reads back the existing clone and verifies checksums again. Contradictory readback blocks completion and preserves the clone for review; originals/export/manifest changes fail validation.

The bundled `probeResolve()` only connects to configured `DaVinciResolveScript` and reads its version. It does not claim a live mutating adapter, identical Free/Studio capabilities, headless support, or that Resolve is installed. The bundled [local SDK worker](resolve-worker.md) targets Resolve 20.2+ within 20.x, baked cut-only video/audio and equal integer FPS. `pnpm resolve:handoff --directory HANDOFF --action probe|execute` uses actual native methods and normalized clip/source readback, preserving the original and clone/import intent. Native captions/retiming/effects are rejected before cloning; sidecars remain separately reviewed. Python fake-SDK subprocess tests are not evidence of installed-editor compatibility. Recovery receipts remain local; manual reconciliation can attach a discovered clone receipt after an ambiguous duplication.

The audited [Resolve MCP readback](https://github.com/samuelgursky/davinci-resolve-mcp/blob/8911bd24aee76894238924317a461005dd013d94/src/utils/readback.py) inspired verification-after-mutation. Its MIT code was read, not copied. OpenCut's MIT rewrite still lists editor API/headless as future work: [the refreshed source audit](opencut-integration-boundary.md) explains why no native adapter is advertised.

## Blender procedural capture

`pnpm tsx scripts/backend.ts --action blender --request capture.json --output DIRECTORY` probes optional Blender 4.2+/5.x, then invokes our own Python worker with factory startup and autoexec disabled. No user `.blend` or generated arbitrary Python is loaded. The small pilot renders a lit cube with configurable color, dimensions, FPS and absolute rotation formula. Frames can be requested in any unique order; frame state is `frame + 1` and rotation derives directly from frame/FPS. Every PNG has matching dimensions and is ffprobe-inspected before immutable publication with hashes/manifest. Worker subprocess environment omits provider API keys. Missing Blender returns structured `state: unavailable` without fabricated outputs. Determinism across sequential/random seek is conditionally tested only when the actual executable is available; complex physics/cache/GPU cross-version determinism is not claimed. See [Blender CLI documentation](https://docs.blender.org/manual/en/latest/advanced/command_line/arguments.html).

The [HTML/Hyperframes seek worker](html-capture.md) provides opt-in offline Chromium capture with explicit local asset allowlist, fresh-document absolute seek, immutable PNGs and optional MP4. `pnpm capture:html --request REQUEST.json --output DIRECTORY` runs real capture; the probe never downloads Chromium. Separate explicit profiles support AVC timing/audio, an async FrameAdapter and a pinned genuine native Hyperframes player/GSAP subset; use each profile's documented media/clock limits and receipt. An explicit macOS decoded-source-proxy-v1 choice adds checked AAC, embedded video audio and original-clock VFR preparation; see the normalization receipt and limits in the capture guide. Existing Remotion frame-clock rules remain unchanged. This is trusted composition execution with process/CSP guards; generalized native runtime compatibility and hostile-code OS isolation remain open.

`pnpm blender:scene --request SCENE.json --dry-run` validates the owned declarative bake without launching Blender. Capture additionally needs new output/cache paths and an explicitly supplied trusted Blender4.5.14 executable. The bounded sphere-contact extension adds opt-in dynamic/static sphere interactions, mass, restitution and sliding friction with deterministic frame states and source/runtime cache pins. The separate solid-sphere rotational v2 adds optional world-space angular velocity, isotropic inertia, friction torque and normalized orientation under explicit `avc-solid-sphere-contacts-v2`. Native quaternion/matrix/Euler readbacks are checked and pinned alongside images. Unsupported overlaps, geometry, excessive travel/spin or unresolved grazing contacts refuse. Old default/v1 bake states and hashes are preserved; shared worker changes intentionally invalidate runtime caches. Imported images/video remain reviewed candidates. Meshes, native Blender dynamics, large/GPU scenes, textured rolling and creative acceptance remain open.

## Blender headless runs

`blender:scene` stays the restricted declarative route, pinned to Blender 4.5.14. For high-end shots, `pnpm exec tsx scripts/blender-run.ts` runs a trusted agent-authored Python script and/or `.blend` in any Blender 4.2+/5.x. Use the [blender-3d skill](../.agents/skills/blender-3d/SKILL.md) to decide whether a shot needs it.

`--action probe --backend blender` searches `PATH`, then `/Applications/Blender.app` and `~/Applications/Blender.app`, and reports `version`, `path` and `routes`: `headless-run`, `procedural-capture`, `declarative-scene` (4.5.14 only), `mcp-official-eligible` (5.1+), `mcp-community-eligible` and `gui`. MCP routes state eligibility only; the probe never installs or connects a server. `--backend yt-dlp` and `--backend hyperframes-cli` report `available` (a route exists through `uvx` or `npx`) and `installed` (it runs without a download). They use `uvx --offline` and `npx --no`, so nothing is fetched.

The runner launches `Blender --background --factory-startup --disable-autoexec --offline-mode --python-exit-code 1 [file.blend] --python avc_run.py -- [script arguments]`. `scripts/workers/blender/avc_run.py` runs the script, applies the command-line settings so they win, picks the Cycles GPU under `--device auto`, and renders `frame-NNNNNN.png` or `.exr` to `--output`. A script is arbitrary Python with the user's permissions; auto-run inside `.blend` files stays disabled. `--no-factory-startup` loads user preferences and add-ons, for runs that need them.

Each run writes `blender.log`, verifies every frame (signature, size, PNG trailer) and hashes it, then writes `preview.mp4` and `contact-sheet.png` through [agent vision](agent-vision.md), and `blender-run.json`. Exit codes, signals and timeouts become typed errors with the log path. A stopped run keeps its frames for `--resume`. `--encode h264` or `prores4444` adds a video; ProRes 4444 keeps alpha, and the PNG sequence is the alpha route inside Remotion. `--project ID --import` imports an H.264 video or a single PNG frame as an immutable asset. ProRes is refused because the registry would store it as MP4. Pass `--metadata` with `rights` and `provenance` for the import and `sources[]` for each third-party file. Without `rights` the asset's licence is `unknown`.

`scripts/workers/blender/avc_export.py` can be imported by any script run this way. `export_camera()` writes `camera.json` per frame: world matrix, three.js Y-up matrix, projection matrix, lens, field of view, focus distance and named anchors as top-left pixels.

The real gated test runs with `RUN_BLENDER_TESTS=1`. Verified on Blender 5.2.3 LTS, macOS, Apple M1 Max with Metal. A silent first-run Metal kernel compile took over five minutes on this machine, so allow for it in `--timeout`. MCP facts, versions, install commands and CVE-2026-66004 are in [MCP routes](../.agents/skills/blender-3d/references/mcp-routes.md).

For an interactive loop, `pnpm blender:live` (MCP `avc_blender_live`) keeps a background Blender scene open on 127.0.0.1 behind a token. It accepts typed edits and kit shots, renders stills to look at, and exports a recipe that `blender:run` replays pixel for pixel on the CPU. The guide is [live session](../.agents/skills/blender-3d/references/live-session.md). Why we chose it over the third-party servers, and their 2026 CVEs: [Blender MCP evaluation](blender-mcp-evaluation.md). Its real test (`tests/blender-live.test.ts`) runs with `RUN_BLENDER_TESTS=1`.

## Poly Haven resources

`pnpm tsx scripts/poly-haven.ts --action search --query sunset --kind hdri` and `--action inspect --id ID` use public metadata GET with injectable offline tests. `--action acquire --id ID --selector '["hdri","1k","hdr"]' --project PROJECT` selects one exact original file, refreshes metadata, restricts download to the official HTTPS host, refuses redirects and verifies declared size/MD5 plus local SHA256. Original bundles are stored without extracting or executing scripts in `assets/resources/poly-haven`; immutable receipts preserve CC0, creator/source and API credit. Limit defaults to 512 MiB. A bundle's referenced materials/textures are not automatically fetched; acquire each selected dependency explicitly.

[Official API page](https://polyhaven.com/our-api) now permits personal and commercial API use (18 July 2026), separately from CC0 assets. The [official API README/terms](https://github.com/Poly-Haven/Public-API) requires a visible “Powered by Poly Haven” credit for products using the live API. Dedicated scripts/classes support HDRI/model artifacts; generic media ResourceService acquisition does not pretend a `.blend` is video/image. Tests do not call the live API.

The Blender pilot was additionally run using official portable Blender 4.5.14 LTS on macOS ARM64. Its PNG wall-clock date/render-time stamps are disabled so repeated identical pixels also retain identical file hashes. The executable was not installed into system applications.  for version, checksum and results.
