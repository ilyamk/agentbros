# Exact offline model discovery

For new tasks, use `pnpm fal:find --task TASK --min-tier verified`; `pnpm fal:models --catalogue --list` inspects the whole offline index. The compatible snapshot view `pnpm fal:models --local --list --limit 1000` exposes all 98 checked schema endpoints, including `fal-ai/kling-video/create-voice`. The default page remains 50 records; metadata includes `total`, `returned` and `truncated` so agents can detect incomplete results. No discovery request or paid submit occurs in local mode.

Each descriptor has readonly typed `requestRouting` copied from the bundled operation snapshot: `family`, `variant`, `operation`, `region`, `transport`. Copy these fields to a `FalOperationRequest`, add exact schema-valid `input`, and validate using `generate:model --dry-run`. Schema/source/date/hash/region evidence comes from that same snapshot. Local `--schema ENDPOINT` returns the actual input/output schemas and their referenced components alongside the existing model descriptor; `--info ENDPOINT` stays compact.

Legacy discovery labels remain compatible: `kling-3` still groups the same endpoints as modern `kling-v3`; gallery endpoints retain descriptor family `flux-2`/operation `style-workflow`, but their exact request route uses `flux-2-gallery`/`edit`. Training labels remain `training` while requests distinguish `train` and `train-edit`; legacy `session` maps to exact `realtime`. Old generation endpoint aliases remain unchanged. A descriptor's compatibility operation is not an exact request payload.

Local CLI `--family`, `--operation`, `--transport` and `--region` select actual routing metadata (family also accepts legacy spelling/grouping). `--category` accepts compatibility operation labels or exact operations. Example: `pnpm fal:models --local --family kling-v3 --operation image-to-video`; `--family kling-voice` finds the separate nonmedia voice operation. Exact filters require local mode. Library callers can use `listModels({requestFamily,requestOperation,requestTransport,region})` for unambiguous exact grouping. MCP `avc_models` accepts modern and legacy family spellings and exposes the same requestRouting fields.

Prices come from exact registry definitions, reviewed tariffs or compatible dated Platform API records; discovery never invents a rate. The six allow-listed FLUX stream endpoints and `fal-ai/flux-2/klein/realtime` report `localAdapter: true`; other stream/realtime routes remain unsupported. Dedicated transport commands retain separate planning and recovery contracts. All descriptors remain `live: false`. Discovery of a route is not a promise that live submission, speech/content policy or funding will pass.

## Whole-catalogue index

The 98 snapshot endpoints above are a subset of fal's catalogue. `pnpm fal:sync` keeps a tracked index of endpoints and their retained statuses in `src/lib/models/fal-catalog/<category>.json`, the full OpenAPI per endpoint in the hash-pinned cache `.cache/fal-schemas/<sha256>.json`, and a drift report (added, gone, schema changed, retiring, demoted). It makes only free read-only GET requests: `--catalog` pages the listing, `--schemas <ids>`, `--tier verified` or `--all` fetch schemas, `--verify-known` looks up indexed endpoints the listing missed and marks a confirmed 404 `gone`, `--pin-verified` fills the pins in `src/lib/models/fal-verified.json`, and `--report` writes `out/qa/model-refresh/fal-catalog-drift.md`. `--from-fixtures DIR --dry-run` runs offline. A mismatched schema hash loses verified status; it falls back to `priced` if a dated price remains, otherwise `discovered`.

`pnpm fal:doctor [--project ID]` is local and read-only: it lists the endpoints the harness and a project reference (legacy aliases, compatibility helpers, the video and lip-sync scripts, the music allow-list, `operations.json` jobs and asset-plan requests) with their catalogue status (`active`, `deprecated`, `gone`, `retiring` with its replacement, or `not-in-catalog`). Contracts and trust tiers: [fal integration](fal-integration.md).
