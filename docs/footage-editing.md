# Editing a user's own footage

Last updated: 2026-11-17

For "cut my video", "remove silences / fillers / ums", "add subtitles", "make shorts from my video", "I have two cameras" and "make it vertical". Every step is local and free except `transcribe`. Every step proposes; a person approves the edit hash or the selection before anything is created. The footage editor agent (`.agents/agents/footage-editor.md`) runs it; the skills are `recording-recut` (cuts, shorts) and `captions-and-localization` (caption styles).

For fal transcription, `transcribe` also accepts `--provider fal --endpoint <id>`; see the [verified speech endpoints](fal-catalogue.md#verified-endpoints) for timing caveats and raw replay.

## Start here: `footage:next`

Put the recording in a source project (`pnpm project:new --project talk`, then `public/projects/talk/assets/footage/`), give the goals once and repeat `footage:next`, doing what it says:

```bash
pnpm footage:next --project talk --goal recut,captions,vertical --formats landscape,vertical --caption-style outline-pop --language en
pnpm footage:next --project talk
```

Goals go to `pipeline/footage-goals.json` (`--goal recut,captions,vertical,shorts,multicam`, `--formats`, `--caption-style`, `--language`, `--source` when the project holds several videos, `--cameras` for multicam, `--transcriber scribe|local`, `--speakers`, `--recut-id`, `--shorts-brief`, the pace `--mid-pause-ms`, `--sentence-pause-ms`, `--punch-in`, which every `recut:plan` it prints repeats, reruns included, and `--placement organic|ad` with `--platform` for a paid vertical cut, which `captions:place` then receives; `--no-save` applies them to one call). `--playbook <id>` binds the source project to a playbook whose route or one of its alternatives is footage (`pipeline/playbook.json`, [playbooks](../playbooks/AGENTS.md)); that route's goals are the default when `--goal` is absent and none are saved, and every answer then reads the playbook first and carries the user's `memory` for that playbook and step (a footage step id such as `5-captions`; [playbooks](../playbooks/AGENTS.md)). State is read from files only, so it works on projects made by hand. A recut or a shorts episode ID resolves to its source project. Working files go to `pipeline/footage/<source name>/`; existing transcripts, masks, shots and plans anywhere under `pipeline/` are found by the source's SHA-256.

The answer is one action:

| `action` | Meaning |
|---|---|
| `run` | Run `commands` in order (`argv` holds the same commands as arrays: do not split the strings yourself), then call `footage:next` again |
| `ask` | Put `question` (with `answers`, files in `show`, `cost` for paid steps) to the user; after their answer run `thenRun`. `userDecides` names what only the user may decide: paid transcription, the edit-hash review, which shorts to approve |
| `agent-task` | Work the agent does itself: shorts candidates, or the speaker map from the still commands in `commands` |
| `stop` | Done, or blocked for a reason in `why` |

`optional` lists what may help (a render excerpt with `--frames`, the delivery check); `advisories` what to know: another recut, a local transcript with few fillers or language `und`, words a local recogniser glued together (with captions as a goal: 18+ letters in Cyrillic or 20+ otherwise, or a Cyrillic word that splits into words used on their own elsewhere; fix the words' text in the transcript or use Scribe), and a format whose crop is enlarged 2x or more (vertical from 640×480 is about 4x). Without goals, the first `ask` covers goals, formats, caption style, language and paid or free transcription with its cost, so the user answers once; `state` summarises what it found. It never writes an approval and never proposes one: the person adds the review with the printed hash to the request, and shorts approval goes through `shorts:request --approved-by` in the user's own words. Under an autonomous policy the user granted (`film:policy` on the source project), it answers the caption style and the shorts approval from the policy's pre-answers through `footage:policy-apply`, logged in `pipeline/decisions.jsonl` and revocable with `film:revert` ([autonomy](production-chain/autonomy.md)); the edit-hash review stays the person's.

The table below is the order it follows and the reference for each command, with one exception: with `shorts` among the goals the shorts (step 6) are the deliverable and come right after captions and crops are placed on the recut; the full recut's renders (step 9) are then only offered in `optional` at the end.

## Order

| Step | Command | When | Guide |
|---|---|---|---|
| 0. Source | `ffprobe -v error -show_entries stream=codec_type,start_time,duration_ts,duration -of compact talk.mp4` | Always, before step 1. Transcripts are bound to the file's SHA-256, so fix the file first or you transcribe (and pay) twice. `recut:plan` needs one video and one audio stream, both starting at 0, with a stream `duration_ts` (WebM/MKV have none; `recut:plan` refuses them with a remux hint), and, for a non-30 fps source, audio ending within one frame of the video (refused with a trim hint). A copy that passes: `ffmpeg -i talk.webm -map 0:v:0 -map 0:a:0 -c:v copy -af atrim=end=<video seconds> -c:a aac -movflags +faststart talk.mp4`; a non-zero video start (WebM remuxes often start at a few ms) needs a re-encode; a variable rate goes through the version 2 normalisation | [recording edit](workflows/recording-edit.md) |
| 1. Transcript | `pnpm speech:local --input talk.mp4 --output out/talk/transcript.json` (free; also writes `speech-mask.json`) or `pnpm transcribe --project talk --input talk.mp4 --output out/talk/transcript.json` (Scribe v3, **paid**: ask first) | Always. `speech:local` is not verbatim: it marks only the fillers Parakeet writes out (English "um"/"uh"; none in Russian), so filler removal needs Scribe; its word times are mostly back to back, so `recut:plan` finds few pauses in it. It labels speakers when `HF_TOKEN` has accepted the pyannote model. Scribe labels speakers with `--diarize`. To rebuild a Scribe transcript after a fix, use `--from-raw` on the saved `.scribe.json` (no spend). It tracks spend in an existing project with a budget: create a source project first (`pnpm project:new --project talk`), never the recut's ID, then `pnpm budget --project talk --ceiling-usd N` | [speech](speech.md) |
| 2. Shots | `pnpm footage:shots --input talk.mp4 --output-dir out/talk/shots` | The recording is already edited (cuts, dissolves) or you will reframe per shot | [footage shots](footage-shots.md) |
| 3. Recut plan | `pnpm recut:plan --transcript out/talk/transcript.json --project-id talk-recut --speech-mask out/talk/speech-mask.json --formats landscape,vertical` | Cuts, silences, fillers, false starts. `--formats` defaults to the source's aspect: list every format the user wants. Writes `recut-request.json` and `recut-plan.md` next to the transcript. Show `recut-plan.md`; rerun with `--reject C3,C7 --force` for refused cuts (`--force` rewrites the request, dropping any `review`). Retakes are proposed from repeated words, so check that a "retake" is not a deliberate parallel ("sometimes more frequent, sometimes more intense") | [recording edit](workflows/recording-edit.md) |
| 4. Create | The person adds `"review": {"reviewer", "reviewedAt" (ISO date-time), "approvedEditHash", "meaningPreserved": true}` with the printed hash; then `pnpm video:workflow --scenario recording-edit --request out/talk/recut-request.json --action create` | Only after that approval | [recording edit](workflows/recording-edit.md) |
| 5. Captions | `pnpm timeline:edit --project talk-recut --revision N --command-file caption-style.json --dry-run`, then again without `--dry-run`, with `{"type":"caption-style","style":{"profile":"outline-pop"}}`; after any reframe, `pnpm captions:place --project talk-recut --format vertical` and apply its `caption-place.json` the same way | Subtitles, placed clear of faces, on-screen text and the platform interface, with measured legibility. Ask which of the ten styles (outline pop, yellow italic shadow, key-word colour, sliding word box, line box, chunky stack, editorial mixed scale, clean sentence, single-word punch, typewriter) when the user has not said; the older ids still work | [caption styles](../.agents/skills/captions-and-localization/references/caption-styles.md) |
| 6. Shorts | `pnpm shorts:prepare`, your candidates, `pnpm shorts:rank --project <id>`, the user's own approval recorded on the CLI by `pnpm shorts:request --project <id> --selections proposals.json --ids c1,c3 --approved-by "<user>"` (typed by the user or relayed verbatim from what they said, never inferred by an agent; over MCP `shorts_request` only writes the chapters) (writes `pipeline/chapters.json` with the recut's protected spans and the series request), then `pnpm video:workflow --scenario shorts-series --action create --request <request>`; `pnpm shorts:calibrate` after ten rated clips | Clips from a long recording. Rank against the project whose timeline you will cut shorts from, uncut or the recut (`--project <id>-recut`): recut clips are found by their `payload.sourceHash`, including a normalised master, and a candidate may cross the recut's pause, filler and retake cuts, mapping to one range on the recut's output; it is rejected only when a cut removes words its quotes cite, or when its span is reordered or interrupted on the timeline. A clip whose first or last word has less than 100 ms of silence beside it starts or ends in running speech: with `--speech-mask` the edge moves into a mask silence of at least 100 ms within 150 ms, otherwise the clip is rejected (not demoted) with that reason; pass `--speech-mask` to give such clips a chance. Without `--project` you get scores but no `ShortSelection` drafts. `shorts-series` also needs a ChapterManifest at the source project's `pipeline/chapters.json` (`ChapterManifestSchema`: chapters and protected spans in output frames); `recording-edit` does not write one, so author it from `recording-edit.json` before ranking. Its request pins the source with `inspectShortsSeriesSource` (no CLI yet) and runs through `pnpm video:workflow --scenario shorts-series --action plan`, then `create` | [shorts selection](../.agents/skills/recording-recut/references/shorts-selection.md) |
| 7. Cameras | `pnpm multicam:sync --inputs wide.mp4 close.mp4 --output out/talk/sync.json`, then `pnpm multicam:angles --sync out/talk/sync.json --output out/talk/angles.json` | Two or more recordings of one event | [multicam and reframing](multicam-reframe.md) |
| 8. Vertical | `pnpm reframe:track --input talk.mp4 --format vertical --output out/talk/crop-path.json` (`--shots` from step 2); for a recut, add `--recording-edit public/projects/<id>/pipeline/recording-edit.json --command-output edit.json --track-id recording-picture --timeline public/projects/<id>/pipeline/timeline-edit.json --clip-id all` and apply the command with `timeline:edit`. To follow the active speaker in wide shots, add `--transcript <diarised transcript> --map angles-map.json`, where the map gives each transcript speaker id its horizontal `position` (0 left, 1 right) in the wide frame: `{"version":1,"speakers":[{"speaker":"speaker_0","angle":"wide","position":0.28},{"speaker":"speaker_1","angle":"wide","position":0.73}],"wide":"wide"}`. Read the positions off a wide-shot still and match ids to faces by who speaks first | A landscape source for a vertical or square film | [multicam and reframing](multicam-reframe.md) |
| 9. Render | `pnpm render --project talk-recut --format vertical --timeline` | After review; delivery is a separate check. It renders the whole timeline (no frame range) to `out/<id>/<format>.mp4`, overwriting the previous render: copy it before rendering another caption style. The render is refused at the end if any input, including files under `src/`, changed while it ran | [delivery](delivery.md) |

Steps 7 and 8 write a timeline command with `--command-output`; dry-run it with `timeline:edit --revision N --command-file ... --dry-run` before applying. `N` is the timeline's current revision, which every edit checks: a new recut starts at 0 and each applied edit adds 1. Apply the vertical crop path before rendering vertical; without it the recut uses a centred cover crop.

## Rules

- Never cut, apply or create without the person's approval of the plan (edit hash, selection hash). Approval is never written by an agent.
- Paid transcription needs the user's go-ahead and budget; resume an interrupted one with the same `--operation-id`.
- Captions come from the same transcript, so the recut keeps them in sync; fillers render only if they survived the edit.
- The original file is never modified; each recut is a new project.
- After the user watches a render, their change requests go through `pnpm feedback --project <id> --file items.json` (preview, then `--confirm`): each item reopens the plan, captions, shorts, reframe or audio levels, and `footage:next` returns that step with their words until its output moves ([feedback](feedback-routes.md)).
